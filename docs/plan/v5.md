# Orrery — the plan, v5

*Working name. "Auto-UI" and Google's "A2UI" are indistinguishable spoken aloud.*

**What changed in v5:** the brief was clarified (`00-brief.md`, 2026-09-19) and the
clarification is structural, not cosmetic. The product is a **persistent space an agent
builds in**, not a chat transcript with widgets embedded in it. That answers the finding
four rounds could not resolve — *framework or application?* — and it demotes the World Bank
statistics browser from "the product" to "one demo".

Facts marked **[measured]** were checked against live APIs or package metadata on the date
given. Facts marked **[asserted]** were not. Round 4 penalised an unverified claim sitting
among verified ones; the labels exist so that cannot recur.

---

## 1. The idea

A **space**: a durable surface that accumulates. You write into it; things appear and stay.
Some stay for a minute, some stay until you delete them, and "stay" means *as long as the
server holding the data does*. An agent builds in this space — placing, updating and removing
elements — and elements in the space can call an agent back.

The agent does not write UI code. It emits **specs**: a few hundred tokens of JSON selecting
and parameterising from a registry of blocks, and **queries**: a closed grammar describing
what data to put in them. The runtime turns those into themed, interactive, persistent
artifacts.

**Why not let the model write React?** Three reasons that do not weaken as models improve,
and one that does:

1. **Persistence.** The space's whole value is that it survives. A JSON spec re-renders in
   two years; stored generated React is a rot-and-security liability the day you persist it.
   This is not a justification bolted onto a design choice — the brief makes it the product.
2. **Theming by construction.** Generated code uses your tokens *most* of the time. A registry
   uses them 100% of the time, and "on theme" is in the brief twice.
3. **Free interaction.** Spinning a globe, sorting a table, scrubbing a year costs 0 tokens
   and 0 network, because the behaviour is compiled in rather than generated. In a space you
   return to, interaction happens far more often than generation.
4. *(Weakens over time)* **Reliability.** Selection from a registry fails less than codegen.
   That gap narrows every model generation. Do not build the case on it.

**Determinism, stated correctly.** Round 4 caught v4 selling determinism as a system property
while accepting an 80% selection-match threshold in the same document. Those are two claims
and v5 separates them:

- **Render determinism** *(guaranteed, testable)*: the same spec produces the same render. A
  renderer property, tested by the conformance suite.
- **Selection stability** *(measured, never guaranteed)*: the same request produces a similar
  spec. Has a threshold and an eval harness, and will never be 100%.

Only the first is load-bearing for persistence, which is why persistence survives the second
being imperfect.

**The ceiling is real and gets an explicit exit.** Some requests have no block. Degrading
silently to a paragraph is the worst outcome, because the user never learns the system could
not. Refusal is therefore a **first-class element type** (§4.6), not an absence.

## 2. What this repo is — the substrate question, answered

Round 4's sharpest finding: *"closed vocabulary" and "works for whatever application" are in
direct tension, three of four "bones" are demo-specific, and there is no extension point —
pick one.* v4 had claimed a platform while building an application.

**The answer: a substrate with an extensible registry, and the extension API is the
artifact.** What is app-independent, and what is not:

| Layer | App-independent? | Contents |
|---|---|---|
| **Space protocol** | Yes — the core | Elements, ids, lifetime, versions, state snapshot, agent callbacks |
| **Query grammar** | Yes | `source × select × entities × range × filter × order × limit` |
| **Asset addressing** | Yes | `asset:pack/name@ver` through a registry |
| **Tokens + emitters** | Yes | `tokens.json` → CSS, TS, canvas/G2 theme, sprite palettes |
| **Block registry** | Extension point | `defineBlock()`; a conformance-gated **core pack** ships with it |
| **Resolvers** | Extension point | `defineResolver()`; World Bank is a *bundled example*, not the core |
| **The geo table** | No — demo asset | A World Bank/Natural Earth join artifact. Ships in the example pack. |

This costs something and v5 says so rather than discovering it in month 3: **with an open
registry, a persisted spec is re-renderable only by a runtime that has the packs it used.**
So every spec carries `requires: ["core@1", "geo@1"]`, and a runtime missing a pack renders a
labelled stub rather than a broken element or a confident lie. Persistence is real but
scoped, and the scope travels inside the artifact.

**Not a novelty claim.** Declarative UI specs are published work (Vega-Lite, NL4DV);
data-by-reference is in the MCP literature. What is unoccupied is narrower and sufficient: a
**persistent, agent-addressable space**, an **asset and theme pack that makes its output look
like one product**, and the licensing work nobody wants to do.

## 3. How it works

```
 you type ──▶ /api/turn ──▶ agent (Sonnet 5)
                              │
                phase 1: prose streams back — qualitative only, NO figures (§3.1)
                              │
                phase 2: tool calls
                              ├── query(...)   ──▶ resolver ──▶ digest ──▶ back to the agent
                              └── place(...)   ──▶ zod validate ──▶ server assigns id
                                                        │
                                             element enters THE SPACE
                                                        │
 you drag / sort / scrub ──────────────────────────────▶ renderer-local state
                              │                            0 model calls
                              │                   refs re-resolve via /api/resolve
                              │
 element's own button ───────▶ invoke() ──▶ agent ──▶ place / update (§4.5)
                              │
 next turn ──▶ agent reads the space snapshot ──▶ grounded narration
```

Four interaction tiers. Blocks declare which they support:

| Tier | Cost | Examples |
|---|---|---|
| **local** | 0 tokens, 0 network | spin, sort, hover, paginate, scrub a cached year |
| **refetch** | network only | a year outside the cache, a different entity |
| **invoke** | model call, budgeted | an element's own button asks the agent something |
| **turn** | model call | you type |

### 3.1 The rule that makes it honest — and the hole v4 left in it

**No figures outside resolved data.** Phase-1 narration streams before any tool returns, so
any number in it is parametric recall.

v4 applied this to narration only, and round 4 found the hole: a phase-2 `Prose` element full
of remembered numbers is *unconstrained and persisted* — strictly worse than a wrong sentence
that scrolls away, because this one is saved, screenshotted and trusted.

**v5 closes it in the validator.** `Prose.text` may contain literal numerals only via a
`figures: []` array of `{$from}` bindings to resolved refs; free-text numerals fail validation
with a repair message the agent can act on. The agent may say "pulling population now"; it may
not say "342 million" unless something resolved it.

*(Concretely: the real 2024 US population is 340,003,797 **[measured, World Bank
SP.POP.TOTL]**. A recalled "342M" sitting above a tile showing the true value is worse than
either alone, because the tile lends it credibility.)*

## 4. The contract

This is the artifact. Round 4's first finding was that v4's version of this section was a
six-row markdown table of prop names — that you could not write `blocks.ts` from it on Monday
morning. Here are the types.

### 4.1 The space, elements, and lifetime

```ts
type SpaceId   = string  // "sp_" + ULID
type ElementId = string  // "el_" + ULID — SERVER-ASSIGNED, never model-invented

type Space = {
  id: SpaceId
  v: 1
  title: string
  elements: Element[]        // ordered; order is layout order
  createdAt: string          // ISO-8601
  requires: string[]         // e.g. ["core@1", "geo@1"]
}

type Element = {
  id: ElementId
  block: string              // registry key, e.g. "core/Choropleth"
  props: unknown             // validated against that block's zod schema
  lifetime: Lifetime
  layout?: { span?: 1|2|3|4; minH?: "s"|"m"|"l" }   // coarse, never pixels
  origin: { turn: number; at: string }
  version: number            // bumps on every update — this is what gives undo
  frozen?: FrozenData        // §4.2 — present iff lifetime.mode === "persistent"
}

type Lifetime =
  | { mode: "ephemeral" }                    // dies at end of turn: status, progress, drafts
  | { mode: "session" }                      // dies when the space closes
  | { mode: "persistent"; pinned?: boolean } // written to the store; survives
```

**Three lifetimes, because the brief says "persistent or temporary, interchangeably."**
Promotion is explicit and cheap — `promote(el, "persistent")` — and available to both the
agent and the user, as a pin button. Demotion is `release(el)`.

**Expiry is never silent.** An expiring element collapses to a **stub**: its title, its block
type, and a "rebuild this" affordance that replays the originating query. Things quietly
vanishing from a space you trusted is the fastest way to make it untrustworthy, and a space
you do not trust is not worth persisting.

**Ids are server-assigned and space-scoped.** Round 4 found that turn 3 and turn 7 both
emitting `b1` makes every binding ambiguous — a correctness bug in the file the plan calls the
contract. The agent emits `place()` with *local placeholder names* (`"$globe"`); the server
assigns the ULID and returns the mapping. The agent addresses existing elements only by ids it
read from the space snapshot.

### 4.2 Persistence, and the freeze

Reason #1 in §1 is persistence, and round 4 found v4's own `mry` ("most recent common year")
falsified it: a spec reopened in 2028 resolves a different year and shows different numbers —
the exact failure v4 indicted `mrv` for. v4's restart test could never catch it, because it
restarts in minutes while the drift is in years.

**The fix is to freeze, and it is not subtle:**

```ts
type FrozenData = {
  at: string                    // when it was frozen
  resolvedYear?: number         // a concrete year, never "mry"
  rows: unknown                 // the resolved values themselves
  receipts: Receipt[]           // source, units, licence, attribution, per ref
  digestVersion: string
}
```

On promotion to `persistent`, every ref resolves once and the **result** is written into the
element. A persisted element renders from its frozen data — offline, forever. That is what
"persists as long as the server holding it does" has to mean; an element pointing at a live
third-party API is not persistent, it is a bookmark.

**Refresh is explicit**: a `refresh` affordance re-resolves and creates **version n+1**,
keeping n. So the space gets undo for free — which round 4 noted v4's snapshot model had
silently removed from the user, leaving them no way back to the country they had selected
before.

`mry` survives only as an *authoring-time* convenience: it resolves to a concrete year the
moment it is used, and the concrete year is what is stored. It also needs a quorum, absent in
v4 — `mry` = the most recent year with ≥ `q`% of requested entities present (default 80) —
and the resolver returns `{resolvedYear, coverage, excluded[]}`, which the renderer must
surface. Without a quorum, "common year" across 217 sparse entities is either a decade stale
or empty, which is how v4's `mry` reduced to `mrv` with extra steps.

### 4.3 The query grammar — the hole v4 left

Round 4's deepest finding: every ref in v4 was a single scalar lookup `{source, entity,
year}`, while every interesting request is a query. Three requests were shown to fail, all at
this grammar. It is also, correctly, the hardest thing here to change later — it is typed into
the contract and sits inside every persisted spec.

```ts
type Query = {
  source: SourceRef
  select: string[]                     // measure ids, e.g. ["NY.GDP.MKTP.KD"]
  entities?: EntitySel
  range?:  { from: number; to: number } | { recent: number } | { at: number | "mry" }
  filter?: Filter[]
  order?:  { by: string; dir: "asc" | "desc" }
  limit?:  number
}

type SourceRef =
  | { registry: string }               // "worldbank" — a REGISTRY KEY, never a URL
  | { dataset: string }                // "ds_…" — the user's own data (§4.4)

type EntitySel =
  | { ids: string[] }                  // explicit
  | { group: string }                  // "countries" | "g7" | "eu27" — a SERVER-SIDE table
  | { all: true }

type Filter =
  | { field: string; op: "eq"|"neq"|"gt"|"gte"|"lt"|"lte"; value: string|number }
  | { field: string; op: "in"; value: (string|number)[] }
```

Four things this buys, each one a round-4 failure:

- **"Compare the G7 over time"** → `{entities:{group:"g7"}, range:{from:1990,to:2024}}`.
  Crucially, **`group` resolves server-side from a versioned table**, not from the model's
  memory. v4's grammar let the model expand "G7" itself, so wrong membership passed silently
  and two runs could legitimately disagree — determinism failing on a trivially common
  request. The table also settles "is the EU a G7 participant?" *once*, visibly, in data,
  rather than per-call in a model's head.
- **"Which countries have the worst air quality"** → `{entities:{all:true}, order:{by:…,
  dir:"desc"}, limit:10}`. The *shape* is now expressible; whether a source exists is a
  separate question, answered honestly by §4.6.
- **"Sort my sales data, top 3"** → `{source:{dataset:"ds_x"}, order:…, limit:3}` — the same
  grammar over the user's own data (§4.4). v4 responded to this finding by adding `sort` to
  `Table`: the verb without the noun.
- **`limit` is a query bound, not a pre-slice.** The renderer receives `limit + context` rows
  and the control stays live, so "top 3" does not destroy the interactivity that was the
  reason to render a table instead of a sentence.

**Price basis is part of the query, not a caveat in prose.** `select` names the constant
series (`NY.GDP.MKTP.KD`) or the current one (`NY.GDP.MKTP.CD`), and a current-US$ series sets
`comparableAcrossTime: false` on the result. When false, **the chart carries the warning** —
not only the narration. Round 4 found v4 put the caveat in the sentence and left the
misleading line in the persisted, screenshot-able artifact: its own §3.1 argument, inverted.

### 4.4 The user's own data

Half the brief — "sort my sales data" — had no path in v4 at all. `Table.rows` was an inline
literal, which means the model retypes the user's data as tokens: blowing the token claim,
capping at a few dozen rows, and introducing transcription error.

```
drop a file / paste  ──▶ POST /api/datasets  ──▶ parse (csv, tsv, json, xlsx)
                                              ──▶ profile; store rows server-side
                                              ──▶ return { id, profile }

type DatasetProfile = {
  id: string; name: string; rows: number
  columns: { name: string; type: "number"|"string"|"date"|"bool";
             nulls: number; sample: unknown[]; distinct?: number }[]
}
```

**The agent sees the profile, never the rows** — the same discipline `digest()` applies to
public data. A 50,000-row CSV costs roughly 200 tokens of profile. Then
`{source:{dataset:"ds_x"}}` uses the identical query grammar, so user data is not a special
case anywhere downstream. This path needs no globe, no geo join, no camera table and no World
Bank licensing, which is why §8 ships it in week one.

### 4.5 Bindings, the space snapshot, and calling the agent

**Bindings** are closed objects, never parsed strings — a parsed dot-path is a
mini-expression-language, and templating a model-supplied value into a request URL is exactly
the injection hole §7 forbids.

```ts
type Binding = { $from: { el: ElementId; field: BoundField } }
type BoundField = "selection" | "selections" | "year" | "range" | "row" | "rows" | "sort"
```

`selections` (plural) exists from day one. Round 4 noted that v4's own demo follow-up — *"why
is it so far behind?"* — is inherently two-country while `selection` was scalar; adding
cardinality later changes every consumer's shape, and users try multi-select in the first
minute.

**The space snapshot** is what the agent reads at the start of each turn: one line per
element, **regenerated from live state, never appended**.

```
[space] el_01J9…A2 Choropleth  sel=[BRA] camera=USA year=2023 life=persistent
        el_01J9…B7 Metric      entity←el_01J9…A2 life=persistent
        el_01J9…C1 Table       ds=ds_sales sort=region:asc limit=3 rows=412 life=session
```

Scope — which v4 left undefined, and which round 4 called the load-bearing ambiguity of the
whole file: **all persistent and pinned elements, plus session elements from the last N turns
(default 3), capped at 40 lines**, oldest session elements dropping first. Past the cap the
line becomes `… 12 more elements (use list_space)`. The cap exists because this grows with the
space and is paid on every single turn (§8.4 prices it).

**The space calls the agent.** New in v5, and required by the brief's *"the space should be
able to reach you or some other API/AI agent."*

```ts
type Invoke = {
  on: "press" | "submit" | "interval"
  prompt: string                  // author-written
  input?: { field: string }       // include an element field in the call
  budget: { maxCalls: number; perDay?: number; maxDepth: number }
  label: string                   // shown on the control; the user always knows
}
```

Four guards, because this is the feature most able to burn money quietly:

1. **Visible.** Any control that will call a model is labelled as such. No hidden calls.
2. **Depth-capped.** An agent-placed element may itself declare `invoke`, but `maxDepth`
   (default 2) bounds the chain. Depth is tracked server-side, never in the prompt, because a
   value in the prompt is a value the model can talk itself out of.
3. **Budgeted per space**, with a ceiling the agent cannot raise — only the user can.
4. **`interval` is opt-in per space and off by default.** A timer that calls a model is a
   standing charge on a space that may outlive the person's interest in it. That is a human
   decision, not a model's.

Failure is visible: a failed invoke leaves the element in an error state with a retry, never a
silent no-op.

### 4.6 Refusal is an element, not an absence

When no resolver covers a request — "worst air quality", where World Bank PM2.5 data is sparse
and stale and Open-Meteo is cut for licensing (§6) — v4's likely behaviour was to fall back to
a `Prose` block and narrate from memory. Round 4: *"the plan specifies validation but not
recovery."*

```ts
// core/Refusal
{ want: string
  why: "no-source" | "no-block" | "out-of-scope" | "blocked"
  detail: string
  suggest?: { label: string; query?: Query }[] }
```

The system prompt lists available sources and block types via `capabilities()`, and the
validator rejects a `Prose` element carrying free figures (§3.1). Between them the cheap wrong
path is closed, and the honest path is *fewer tokens* than the dishonest one.

**This is also the demo's best moment** (§8.5): a skeptic typing something out of vocabulary
and watching the system say precisely what it cannot do is more convincing than any rehearsed
frame.

### 4.7 The core pack

Eight blocks. Each has a zod schema in `packs/core/blocks.ts`; this table is an index, not the
definition.

| Block | Required | Local interactions | Tiers |
|---|---|---|---|
| `Prose` | `text` | — | local |
| `Metric` | `group[]` | — | local, refetch |
| `Table` | `query` \| `rows` | sort, filter, paginate | local, refetch |
| `Chart` | `query`, `mark?` | hover, legend toggle, brush | local, refetch |
| `Choropleth` | `fill` | drag-rotate, tap-select, **scrub year**, **pinch-zoom** | local, refetch |
| `Stack` | `children[]` | — | local |
| `Refusal` | `want`, `why` | — | local |
| `Note` | `text` | edit in place | local |

`mark` is an optional one-word hint (`line|bar|area|table|number|map`); **encoding is derived
from the resolved data's shape** — a published approach with a long lineage (Vega-Lite,
APT/"Show Me", Draco). This shrinks the model's surface and removes its opportunity to pick a
wrong scale or forget `entities:"countries"`, making both renderer decisions instead. It is
§4.8's rule 1 applied one level further up.

**Year scrub and pinch-zoom are `local`, in the core pack, on day one.** Round 4 found v4 had
deferred the year slider as "app chrome, the commodity" when it is the *primary control of the
hero block*, and had no tier at all for pinch — the most reflexive gesture on a map on a
phone. Both would have made the most-attempted interactions cost a model call and 3–5 seconds.

**Deferred, out loud:** relational/diagram blocks (`Tree`, `Flow`, `Network` — a GPT-Vis
adapter, costed at ~4 days in §8, not labelled "optional", because diagrams are one of the
brief's three named examples); `Form`/`Slider` as standalone chrome; `Map` with real tiles
(needs a geocoder); sub-national geography — world-atlas carries only `['countries','land']`
**[measured]**, so `"US-TX"` cannot render at any effort.

### 4.8 Prop rules

1. **Data-shaped, not pixel-shaped.** No `width`, `margin`, `className`. Colour only through
   semantic enums. *Admitted exception:* `align` on table columns — the model knows a column is
   numeric before the theme does.
2. **Flat, except per-column and per-series descriptors.** Tables are irreducibly configured;
   that is why TanStack Table is headless.
3. **Enums over free strings.** *Admitted exception:* `iso3`, validated against the geo table
   rather than an enum.
4. **≤8 props, ≤3 required.** `Table` and `Chart` are exempt and documented.
5. **Everything optional renders.** A half-streamed spec must draw something.
6. **`settled`, defined rather than asserted.** Round 4 found v4 claimed it "kills streaming
   jitter as a class" with no mechanism and no answer for a stream that pauses. A block is
   settled when the tool call that produced it closes, **or** after 400 ms with no new patch —
   whichever comes first. And the part v4 got backwards: **a settling element reserves its
   declared `minH` from mount**, so resolving it does not shove everything below it down the
   page. Solving jitter inside a block by moving the whole document is not solving jitter.
7. **Mobile behaviour is declared per block**, now at 8 blocks, not later at 24.

## 5. Assets — half the brief, absent from v1–v4

The brief asks for "free sprites, UI elements, pixel art, painting software, mesh/model
software", and for things made ourselves where possible. v4 never used the word "icon". This
is the section that decides whether output looks like one designed product or like a chart
library with a dark mode.

### 5.1 What ships, licences verified

**[measured 2026-09-19, npm registry]**

| Pack | Version | Licence | Verdict |
|---|---|---|---|
| `lucide` | 1.47.0 | **ISC** | **Ship.** Permissive, no attribution burden, 1500+ icons, one visual system. |
| `material-symbols` | 0.47.4 | **Apache-2.0** | **Ship** as the fallback set. |
| `@fontsource/inter` | 5.3.0 | **OFL-1.1** | Ship. Self-hosting is distribution → needs a `licenses/` build step. |
| `openmoji` | 17.0.0 | **CC-BY-SA-4.0** | **Do not ship in core.** |

**OpenMoji is the Wikipedia finding again, in a new place.** Share-alike propagates: shipping
CC-BY-SA art inside a themed pack puts a copyleft obligation on the pack, and every downstream
commercial user inherits it. It goes into an optional pack flagged `shareAlike: true`, or it
does not ship. The same test cut Open-Meteo in §6. By now it should be a reflex applied to
every asset before adoption, not a discovery made once per round.

**Pixel-art and game-UI sprites [asserted — verify before relying].** Kenney's packs are
widely distributed as CC0 and are the natural core sprite source; Game-icons.net is CC BY 3.0
(attribution, no share-alike). Neither was verified against its live licence file in this
round, and both are load-bearing for "on theme" — so **A2 opens with a licence audit** that
generates `THIRD_PARTY_ASSETS.md` from each pack's own licence file, and CI fails any asset
with no recorded licence. That is the same gate §6 applies to data sources, which is the point:
one rule, both kinds of third-party material.

### 5.2 How a model addresses an asset

```ts
type AssetRef = { pack: string; name: string; v?: string }   // {pack:"core", name:"chevron"}
```

Never a URL, never a path — the same closed-reference rule as `source` in §4.3, for the same
injection reason. An unknown asset resolves to a labelled placeholder, never a broken image.

### 5.3 "On theme" is a recolour pipeline, not a generator

The honest version of "or better yet make them ourselves": **do not plan to generate sprites.**
Producing on-theme pixel art at consistent quality is not a week of work, and it does not
belong on the critical path of a project whose thesis is elsewhere.

What is cheap and captures most of the value: **a build-time recolour pass.** Source art is
authored or sourced in a flat indexed palette; `tokens.json` maps palette slots to theme ramps;
the emitter produces a themed variant per theme. Flip the token file and the sprites change
with the CSS. That is §5.4's single-source-of-truth argument extended to art — a few days, not
a research project, and it makes the token-flip demo genuinely impressive instead of a palette
swap (§8.5).

**3D and meshes are deferred, explicitly.** The brief mentions mesh/model software. A 3D tier
means a format decision (glTF), a renderer that is not the SVG/DOM one, a licence surface, and
an accessibility story with no good answer. It is a second product. Deferred with reasons
rather than dropped silently — and §1's persistence argument is *stronger* for a 3D scene than
for a chart, so this is a real future direction, not a polite no.

### 5.4 Tokens

Source of truth is `tokens.json` (DTCG-shaped), **not a CSS file** — CSS custom properties
never reach a canvas `fillStyle` or a WebGL uniform. Emitters produce `theme.css`, `tokens.ts`,
a GPT-Vis/G2 theme object, and the sprite palette maps (§5.3). Ramps are authored in OKLCH so
light and dark derive from one definition; a separate categorical data palette, contrast-
validated in **both** themes.

**The claim, bounded honestly:** one token source generates our CSS variables, a matching G2
theme object, a validated palette and the sprite recolours — about a week. **"A canvas chart
and a DOM card look pixel-identical" is not deliverable** and is not claimed: canvas has no CSS
cascade, and G2 re-derives ramps through d3-color in sRGB, voiding OKLCH evenness exactly at
the choropleth legend. What breaks first and most visibly is the **dark-mode toggle** — CSS
flips instantly while canvas lags, through a different API. Budget a runtime theme-push on
`matchMedia`. Staying on SVG/DOM for slice 1 (§6) makes this mostly moot, which is a further
argument for it.

## 6. The spatial block, and the data layer

### 6.1 Build the globe with `d3.geoOrthographic`, not WebGL

A drag handler updating `.rotate([λ, φ])` gives a genuinely spinnable globe from the *same*
`d3-geo` and the *same* 38 KB topojson already loaded. Round 4 called this the single best
engineering call in the plan and it stands unchanged.

**Measured sizes** (esbuild + gzip -9, because bundlephobia reports a broken 709 B for
`d3-geo`): `d3-geo` alone **14.7 KB gz**; the realistic day-1 set (`d3-geo` + `topojson-client`
+ `d3-scale` + `d3-scale-chromatic`) **17.8 KB gz**; plus `world-atlas` 110m at **38.4 KB gz**.
So **~56 KB against ~600 KB**.

That one decision deletes from the critical path: a ~559 KB gz / 2.0 MB parsed bundle;
`h3-js` (213 KB, for a hexbin layer never used); a static `three/webgpu` import (2.28 MB) whose
tree-shaking is a coin flip; three copies of three.js (globe.gl pins it, three-globe peers it,
json-render ships an R3F renderer) failing as silent `instanceof` errors; and **`globe.gl`
reading `window.THREE` at module scope, which throws in Node** and would have forced
`dynamic(ssr:false)`, keeping the globe out of the server-streamed paint entirely.

**Scope it honestly.** "~30 lines" describes the *rotate handler*. Canvas hit-testing, the fill
scale, the legend, the halo channel, `settled`, and the mobile scroll rules are not in it —
round 4 caught that overclaim. The block is **~3 days**, of which the rotation is an hour. The
"60fps on a phone at 177 polygons" figure remains **[asserted]** and gets measured in A2 on a
real mid-range device; it is the one performance number in a document that measures everything
else.

### 6.2 The country-code join — an hour, and then a camera table that is not in the hour

`world-atlas` features carry only `{name}` in `properties`, but **their `id` is the ISO-3166-1
numeric code** as a zero-padded string (`"840"`, `"250"`). Missing that is what made earlier
estimates read 2.5 days.

Measured against live data:

- `i18n-iso-countries` `numericToAlpha3` resolves **174 / 177**; the three misses are exactly
  the three features with no `id`.
- Joined to the live World Bank list (`region.id !== 'NA'` → 217 countries): **169 / 174**.
- **Total hand-adjudication: one override (Kosovo → `XKX`).**
- Generated at build time and vendored: **175 entries, 902 bytes gzipped.**

**The exclusion list, stated once as one list** rather than left as arithmetic for the reader:
N. Cyprus, Somaliland, Kosovo *(no `id` in world-atlas)*; W. Sahara, Falklands, Fr. S.
Antarctic, Taiwan, Antarctica *(valid ISO code, genuinely no World Bank row)*. Eight of 177.
The CI test — "every polygon either joins or is on this list" — is ~15 lines.

**Stay on 110m.** 50m is 230 KB gz *and makes the join worse*: five no-id features plus a
duplicate id `036` shared by Australia and Ashmore & Cartier, so `new Map(...)` silently drops
Australia.

**`focus` needs a vendored camera table, and it is a separate ~half-day** — not folded into the
"one hour". Computed centroids fail: `geoCentroid(France)` is open ocean off Portugal (French
Guiana drags it); `geoBounds` on Russia and Fiji returns `maxLon < minLon` across the
antimeridian; the USA's bounds span 105° because of the Aleutians. ~40 entries, generated once,
hand-corrected.

**Disputed boundaries are data, not contract.** Natural Earth encodes editorial choices on
Kashmir, Crimea, Taiwan and Western Sahara. `entities:"countries"` stays defined by World
Bank's own `region.id !== 'NA'`, and territory policy lives in **versioned geo data with an
override map** — never a `"sovereign"` enum in the block schema, which would force every
conforming renderer to agree on a list of sovereigns in order to be conformant.

**Mobile rules, in the block spec:** wheel never zooms; globe ≤55vh so there is always a scroll
gutter; below 600px a one-finger drag must not steal the page scroll that lets someone read the
rest of the answer. Pinch zooms (§4.7).

### 6.3 `digest()` — and why the naive version launders errors

The model never sees rows. It calls `digest()` and narrates from that. The naive nine-field
version `{min,max,first,last,delta,cagr,units,n,outliers}` is actively dangerous — measured
against the live API:

- **It truncates silently.** World Bank's default `per_page` is **50**. A BRA+USA 1990–2024
  call needs 70 rows, returns 50, and the USA's `first` becomes **2010 instead of 1990** — so
  `delta` spans 14 years instead of 34. Well-formed object, wrong numbers, HTTP 200 throughout.
- **`units` cannot be populated.** World Bank's `unit` field is an **empty string** on both the
  observation and the indicator metadata; it must be scraped from the indicator name.
- **Nominal vs real is unrepresentable.** Brazil's GDP CAGR is **5.24%** in current US$ and
  **2.36%** in constant 2015 US$. The series also shows a 44% "collapse" from 2011 to 2020 that
  is almost entirely currency depreciation. `outliers` makes this *worse*: 2011 and 2020 are FX
  artifacts, and flagging them invites the model to narrate them as economic events.
- **`n` hides gaps.** Syria 1990–2024 has 2 nulls. Two series with `n:33` can be consecutive or
  war-shaped, and the model draws a trend line through the hole.

A digest that cannot say "this number is not comparable across time" is not a safety mechanism.
It is a laundering mechanism: it converts the model's uncertainty into a structured,
authoritative-looking object.

**The shape that works:**

```ts
{ first: {year, value}, last: {year, value}, min, max,
  n, nMissing, gaps: [[y, y]],
  cagr, priceBasis: "current" | "constant-2015" | "ppp", currency,
  comparableAcrossTime: boolean,
  units, unitsSource,
  series12: [...],        // ≤12-point resample — closes the whole
                          // "when did X happen / who overtook whom" class
  caveats: string[] }     // current-US$ emits a MANDATORY caveat that
                          // §4.3 routes onto the CHART, not just the prose
```

`NY.GDP.MKTP.KD` (constant) and `NY.GDP.PCAP.CD` (per capita) ship first-class — per capita is
usually the honest answer to "why is it behind" ($10.3k vs $86k), and the naive digest pushes
the model toward the wrong comparison.

**The resolver is server-side.** Not for CORS — World Bank sends
`access-control-allow-origin: *` — but because rate limits would be charged against each end
user's IP, browsers cannot set the `User-Agent` Wikimedia's policy requires, and there is no
cross-user cache. Its real work: pagination, aggregate filtering (a second metadata call),
cache keying with the resolver version in the key, single-flight dedup, and **a monotonic
request token per element** so tapping Brazil-then-China quickly cannot leave Brazil's data
under China's label.

**Abort tokens ship in Phase A, not Phase B.** Round 4 found v4 scheduled them five weeks after
the demo, which guarantees the mislabelled-data bug is live during the entire period anyone is
watching. It is a counter and a comparison; it is not five weeks of work.

Error taxonomy from measured behaviour: a bad indicator returns **HTTP 200 with an error
envelope**, and the genuinely silent case is a *valid* code with no data → `value: null`.

**Licensing, all verified.** World Bank CC-BY, attribution propagates to every rendered chart
(and into `FrozenData.receipts`, §4.2). **Open-Meteo's free tier is non-commercial only — cut
from defaults**, or every downstream commercial user inherits a ToS breach. **Wikipedia is
client-impossible** and CC BY-SA share-alike. REST Countries is an unmaintained single point of
failure — vendor a snapshot. Every resolver descriptor carries
`{license, attribution, commercialUse}`; CI fails one without an attribution string and
generates `THIRD_PARTY_DATA.md`.

## 7. Safety

`Prose` renders markdown through a named sanitizer, no raw HTML. Image URLs resolve through
the asset registry (§5.2) or an allowlist proxy. **`source` strings are parsed against a
registry of known resolvers, never templated into a URL** — which is why bindings are closed
objects (§4.5) and why `AssetRef` is not a path. No prop accepts an arbitrary URL scheme.

**Uploaded datasets** (§4.4) are a new surface v4 did not have: size caps, a parser timeout,
type sniffing rather than trusting the extension, per-space storage quotas, and formula
stripping on xlsx ingest. Datasets are scoped to the space and never cross-readable.

**`invoke`** (§4.5) is the other new surface: server-side depth counting, a per-space budget
the agent cannot raise, and no user free-text reaching a prompt without passing the same
validation as a turn.

**Accessibility is a safety-class requirement here, not a polish item.** Round 4: the doc made
the "retrofit across every renderer later" argument about attribution and never applied it to
a11y — the more expensive retrofit, and the one that blocks shipping commercially.

- **SVG/DOM is the default substrate**; canvas is an optimisation adopted only where measured,
  and always with a DOM shadow tree carrying the same data.
- Every block declares a **keyboard path**. The globe: arrow keys rotate, `Tab` cycles
  countries in the current fill order, `Enter` selects.
- Every data block exposes a **table view** of its own data — which doubles as the
  copy/export affordance round 4 found entirely absent.
- Conformance suite includes axe checks; the static-SVG renderer (§8) makes the "what does this
  element *say*" question answerable mechanically.

## 8. Implementation

**Team size: one.** Round 4 noted "9–11 working days" was stated without one, which changes
whether the back half is five weeks or fifteen. Every estimate below is one person's working
days.

**The bones — what survives a rewrite:** the space protocol (`space.ts`) · the query grammar
(`query.ts`) · `blocks.ts` + `defineBlock` · `tokens.json` + emitters · the asset registry.
**`resolve.ts` is innards** — HTTP, caching, adapters, happily rewritten. Round 4 argued the
ref shape belongs with the bones and not the innards; v5 agrees by moving the *grammar* into
its own file and leaving only the *fetching* in `resolve.ts`.

**Separation gets proven, not asserted.** Disposability means *a second renderer passes a
conformance suite* — not a lint rule. The second renderer is a **static SVG** one covering
`Prose` + `Metric` + `Table` + `Choropleth`: no React, no DOM, no interaction. It forces "what
to draw" apart from "how to draw it" on blocks that matter, and it is independently useful for
email, PDF, OG images and the a11y story.

**Stack:** Next.js (App Router) + React + TypeScript + zod + Anthropic SDK + d3-geo/topojson.
`@json-render/core` sits behind our own adapter interface (§2).

### 8.1 Phase A — prove the thesis (~12 working days)

| # | Step | Days | Kill criterion |
|---|---|---|---|
| **A0** | **Binding loop on fixtures, first thing.** Two hardcoded specs, a `<select>` standing in for the map, one metric tile, one persisted element reopened. No model, no d3, no API. | 0.5 | If `$from` + snapshot + reopen does not work, stop — it is the thesis. |
| **A1** | Spikes: strict-mode schema sanitizer; text-then-tool-call portability. **Verify the `strict:true` grammar claim** — round 4 flagged it as the one major technical claim not marked measured, and A1's kill criterion and A3's cost both hang off it. | 1 | zod emits `minLength`/`minimum`/`maxItems`, which strict mode **400s**. |
| **A2** | **`Table` over an uploaded CSV, end to end.** Upload → profile → query → sort/filter/paginate → promote to persistent → reopen. Plus the asset licence audit (§5.1). | 2 | Half the brief, shipped in week one, with no globe in it. |
| **A3** | Space shell: place/update/remove, three lifetimes, stubs, versions, undo, the snapshot with its cap. | 2 | Reopen a space after a server restart and get the same render. |
| **A4** | `Choropleth` + orthographic drag + geo join + camera table + year scrub + pinch. | 3 | Every one of 177 polygons joins or is on §6.2's list of eight. |
| **A5** | 8 schemas → `strict:true` tool → turn loop with two-phase streaming → `Refusal` path. | 2 | **Threshold written before running:** 20 prompts × 3 samples, ≥80% block-type match, **zero invalid indicator codes**, and **every out-of-vocabulary prompt produces a `Refusal`, never a Prose block with figures.** |
| **A6** | `tokens.json` + emitters, light/dark, a second theme, sprite recolour. | 1.5 | Does the same space read as a different product? |

**The eval harness is in A5, not Phase C.** Round 4's strongest structural finding: the prompt
is the product, `catalog.prompt()` regenerates on every schema change, and the only instrument
that would detect decay was scheduled as optional. A plan that measures its thesis once and
then keeps changing the thing being measured has the detector switched off. Threshold, held-out
prompts, and scoring on *acceptable sets* (a single gold label punishes correct behaviour —
"show me America" has several defensible answers) all land here.

### 8.2 Phase B — each week ships something visible (~5 weeks)

Round 4's "what kills it in month 2": *five weeks of extraction, sandbox, conformance, second
renderer and full resolver immediately after the demo, every item leaving the product looking
identical to the recording already shot — glue with no second thing to glue.*

So Phase B is reordered so that **every week changes what a user sees**:

| Week | Ships (visible) | Carries (invisible) |
|---|---|---|
| B1 | `Chart` + `Prose` + `Note`, GPT-Vis adapter + G2 theme | measure encoding-from-shape |
| B2 | **Diagrams** (`Tree`/`Flow`/`Network`) — a named example in the brief, ~4 days as an adapter | pack boundaries |
| B3 | `invoke`: elements that call the agent, with budgets visible in the UI | depth/budget server state |
| B4 | Sharing: a space opens read-only by link, rendered by the **static-SVG renderer** | conformance suite, the disposability proof |
| B5 | Full resolver: pagination, aggregates, cache, attribution, nightly live-drift job | recorded fixtures |

**The second application is B4's read-only renderer**, and that is deliberate. It is the
smallest real second consumer of the contract, it proves separation by existing, and it gives
the extraction work a user — which is precisely what round 4 said month 2 lacked.

### 8.3 Phase C — genuinely optional

`migrations/` · pixel goldens · sub-national geography if a geocoder lands · a 3D tier (§5.3) ·
`globe.gl` if orthographic proves limiting.

### 8.4 What a conversation costs

Round 4: *"nobody has priced a 10-turn conversation."* **[asserted — these are arithmetic on
stated budgets, to be measured in A5, not observed figures.]**

| Item | Tokens |
|---|---|
| System prompt (`catalog.prompt()` over 8 blocks + query grammar + capabilities) | ~2,000–3,000 |
| Space snapshot, at the 40-line cap | ~600 |
| One `place()` spec | ~250 |
| One digest with `series12` | ~400 |
| **Turn 10, input** | **~4,000–5,000** |

Two things follow. **The system prompt grows with every block added** — that is the real
scaling cost of the approach, and it is why the core pack is 8 blocks and extensions are
per-app rather than global. And the snapshot cap is not a nicety: without it, a long-lived
space makes every turn more expensive forever, which is a uniquely bad property for a product
whose selling point is that spaces are long-lived.

### 8.5 Done looks like

The recording, honestly scoped: it proves **the space**, not that the vocabulary generalises.

A stranger opens a space, drops in a CSV, and gets a sortable table. They ask about America,
get narration immediately and a globe they can drag, tap Brazil, scrub the year — no model
calls. They close the tab. **They come back the next day and it is all still there**, rendering
from frozen data, showing the same numbers. They pin one element, let another expire and watch
it leave a stub rather than vanish. Then they flip one token file and the identical space
re-renders as a visibly different product, sprites and all.

**Then the part that is not rehearsed, and matters more:** the skeptic types three prompts of
their own, one deliberately out of vocabulary, and the system says precisely what it cannot do
instead of bluffing. Round 4 was right that a recording cannot distinguish a generated spec
from a fixture — especially when §8.1 builds fixture replay. Unrehearsed input from the person
being convinced is the only thing that can, and refusal is the plan's strongest and
least-shown idea.

**The falsifiable claim is A5's**, not the movie: 20 prompts × 3 samples, ≥80% block-type
match, zero invalid codes, zero unrefused out-of-vocabulary prompts, threshold written first.
If the recording exists and A5's numbers hold, the thesis is proven. If only the recording
exists, a globe is proven.
