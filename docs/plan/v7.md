## 1. The idea

A **space**: a durable surface that accumulates. You write into it; things appear and stay.
Some stay for a minute, some until you delete them, and "stay" means *as long as the server
holding the data does*. An agent builds in this space — placing, updating and removing
elements — and elements in the space can call an agent back.

The agent does not write UI code. It emits **specs** (a few hundred tokens of JSON selecting
and parameterising blocks from a registry) and **queries** (a closed grammar describing what
data goes in them). The runtime turns those into themed, interactive, persistent artifacts.

### 1.1 The user of this system is a model

The author writing into a space is **a sufficiently sophisticated model**, not a human. Where
human and model ergonomics diverge, this system optimises for the model:

- **A closed vocabulary beats a flexible one**, because the failure mode being designed
  against is plausible-but-wrong generation, not limited expressiveness.
- **Encoding is derived, not specified.** The agent emits a query and at most a one-word mark
  hint; scale, axes, legend and colour channel are the renderer's job. Every parameter removed
  from the agent's surface is a parameter it cannot get subtly wrong.
- **Validation errors carry repair instructions**, because the consumer of an error message is
  something that will retry, not something that will read documentation.
- **The system prompt is generated from the schemas**, so the schemas *are* the docs and
  cannot drift from what the validator enforces.

A human drives this too, through the renderer's own controls. The places where the contract's
shape costs human convenience are deliberate.

### 1.2 Why not let the model write React?

1. **Persistence.** A JSON spec re-renders in two years; stored generated React is a rot-and-
   security liability the day you persist it.
2. **Theming by construction.** Generated code uses your tokens *most* of the time. A registry
   uses them 100% of the time.
3. **Free interaction.** Spinning a globe, sorting a table, scrubbing a year costs 0 tokens and
   0 network. In a space you return to, interaction vastly outnumbers generation.
4. *(Weakens over time)* **Reliability.** Selection from a registry fails less than codegen.
   That gap narrows every model generation; do not build the case on it.

### 1.3 Determinism, stated correctly

- **Render determinism** *(guaranteed, tested)*: the same spec produces the same render. A
  renderer property, verified by the conformance suite.
- **Selection stability** *(measured, never guaranteed)*: the same request produces a similar
  spec. Has a threshold and an eval harness, and will never be 100%.

Only the first is load-bearing for persistence, which is why persistence survives the second
being imperfect.

**The ceiling gets an explicit exit.** Some requests have no block. Degrading silently to a
paragraph is the worst outcome, because the user never learns the system could not. Refusal is
a first-class element type (§4.7).

### 1.4 The prototype inside this plan

The brief asks for a prototype whose top half gets thrown away. Parts of this document —
retention policy, quotas, egress controls, a licence-audit gate — are the *product's* plan, and
building them before the thesis holds would be a mistake.

So they are marked **[policy]**: decided now because the decision shapes the contract, built
later. **The v0 that validates the thesis is A0–A3 plus A6** — a space, typed elements over
uploaded data, persistence across a restart, and an eval number. That is roughly 8 working days
and it either proves the idea or kills it. Everything after it is earned.

## 2. The substrate, and its extension API

### 2.1 Core versus packs

| Layer | Core? | Contents |
|---|---|---|
| Space protocol | Core | Elements, ids, lifetime, versions, snapshot, invoke, access |
| Query grammar | Core | `source × select × entities × range × filter × order × limit` |
| Asset addressing | Core | `{pack, name}` through a registry |
| Tokens + emitters | Core | `tokens.json` → CSS, TS, G2 theme, sprite palettes |
| `digest()` | Core | **First-party. See §2.3 — this is why packs stay declarative.** |
| Blocks | Pack | `core@1` ships 8; others register |
| Resolvers | Pack | `worldbank` is a bundled *example* (Appendix A) |
| Geo table | Pack | A World Bank/Natural Earth join artifact, in `geo@1` |

### 2.2 `defineBlock`, and why rendering is registered separately

```ts
type BlockDef<P extends z.ZodType> = {
  name: string
  props: P                        // SOURCE OF TRUTH for prompt, validator and docs
  tiers: Tier[]
  fields: BoundField[]            // what other elements may bind to
  mobile: { minH: "s"|"m"|"l"; gestures: Gesture[] }
  a11y: { role: string; keyboard: string }        // required — §7.6
}

declare function defineBlock<P extends z.ZodType>(def: BlockDef<P>): BlockDef<P>

/** Renderers are registered per (pack, block, target) — NOT a field on BlockDef. */
type RenderTarget = "react" | "svg-static" | "ink"
declare function registerRenderer<P extends z.ZodType>(
  pack: string, block: string, target: RenderTarget,
  render: (props: z.infer<P>, ctx: RenderCtx) => unknown
): void

type PackDef = {
  id: string
  version: number                 // MAJOR only; see §2.5
  blocks?: Record<string, BlockDef<any>>
  resolvers?: Record<string, ResolverDef>
  assets?: AssetPackDef
}
declare function definePack(def: PackDef): PackDef
```

**Rendering is separate from definition** because the repo has three renderer targets (§8.1):
the React renderer, the static-SVG one, and whatever comes later. A single `render` field on
`BlockDef` could only serve one of them. Splitting it also means a block's *contract* can be
published and validated by a runtime that cannot draw it — which is what makes a missing-pack
stub (§2.5) able to show frozen data as a table.

### 2.3 `defineResolver` — a resolver is data, and `digest()` is not

```ts
type MeasureDef = {
  id: string                      // "NY.GDP.MKTP.KD"
  label: string
  units: string                   // DECLARED — never scraped, never a second HTTP call
  priceBasis?: "current" | "constant-2015" | "ppp"
  currency?: string
  comparableAcrossTime: boolean   // false ⇒ §4.3 routes a caveat onto the CHART
}

type ResolverDef = {
  id: string
  measures: MeasureDef[]          // what `select` may contain
  entities: EntityDef             // how `entities` resolves; named groups live here
  request: {
    base: string                  // fixed host, allowlisted at install AND request time
    path: PathSegment[]           // literals and NAMED SLOTS only
    query: Record<string, ParamSlot | string>
    paginate: { style: "page"|"cursor"; pageParam: string; sizeParam: string; max: number }
  }
  response: { rows: Path; value: Path; year?: Path; entity?: Path }   // restricted subset §7.3
  licence: { spdx: string; attribution: string; commercialUse: boolean }
  cache: { ttlSeconds: number; keyFields: string[] }
}
```

**`digest()` is first-party platform code, and that is the design, not an oversight.** A
resolver's only job is to return normalised rows. Everything the digest does — CAGR, gap
detection, the `series12` resample, the `mry` quorum — is computed by the platform over those
rows, so **every third-party pack gets the rich digest, not the naive one**. The parts that
genuinely are source-specific become *declared metadata* rather than code: `units`,
`priceBasis` and `comparableAcrossTime` live in `MeasureDef`, which is why no second metadata
call is needed and why the empty-`unit`-field problem (Appendix A) is solved by declaration.

This is the line that keeps the security model and the quality bar compatible: **packs declare,
the platform computes.**

**A code-backed resolver tier is deliberately absent.** It is the obvious next ask and it is a
sandbox project with its own threat model. When a source genuinely cannot be described
declaratively, that is the moment to design the sandbox.

### 2.4 Who may publish a pack

Blocks contain a `render` function, which is code (§7.4). Therefore, for as long as there is no
renderer sandbox: **there is no open block registry.** Packs are first-party or vendored by the
space owner, installed deliberately, at the same trust level as an npm dependency — and the
document says that plainly rather than implying a marketplace. Resolver packs, being pure data,
*can* be third-party (§7.3).

**[policy]** An open block registry requires the renderer sandbox in §7.4, and that is a
separate project with its own plan.

### 2.5 Pack versioning **[policy]**

Every spec carries `requires: ["core@1", "geo@1"]`.

- **Within a major, block props are additive-only** — new optional props, new enum members at
  the end. A `core@1` spec renders on `core@1.x` unchanged.
- **A major bump keeps the old renderer.** `core@2` ships *alongside* `core@1`. Old renderers
  are pure functions over frozen data, and keeping one is cheaper than a migration that could
  silently change what a saved artifact says.
- **Retention: majors are supported for 5 years** from supersession, after which a spec renders
  as a stub. This is a policy decision with no code behind it until the B phase; it is made now
  because "how long is forever" is the question the persistence ask raises, and leaving it
  unanswered is worse than answering it provisionally.
- **A missing pack renders a labelled stub** — title, block type, the pack it needs, and its
  frozen data as a table. A stub is a failure; the point is that it is a legible one that still
  shows the data.

## 3. How it works

```
 you type ──▶ /api/turn ──▶ agent
                              │
                phase 1: prose streams to the space's LOG — no figures (§3.1)
                              │
                phase 2: tool calls
                              ├── query(...)   ──▶ resolver ──▶ digest ──▶ back to the agent
                              └── place(...)   ──▶ zod validate ──▶ server assigns id
                                                        │
                                             element enters THE SPACE
                                                        │
 you drag / sort / scrub ──────────────────────────────▶ renderer-local state, 0 model calls
                              │                   refs re-resolve via /api/resolve
 element's own control ──────▶ invoke() ──▶ agent ──▶ place / update (§4.6)
                              │
 next turn ──▶ agent reads the space snapshot ──▶ grounded narration
```

**Phase-1 prose streams into the space's log, not into an element.** The log is the input
channel's own history: it scrolls, it is `ephemeral`, and nothing survives from it unless
promoted. Two-phase streaming is kept for perceived latency without smuggling a transcript back
in as the container.

| Tier | Cost | Examples |
|---|---|---|
| **local** | 0 tokens, 0 network | spin, sort, hover, paginate, scrub within the envelope |
| **refetch** | network only | a year outside the envelope, a different entity |
| **invoke** | model call, budgeted | an element's control asks the agent something |
| **turn** | model call | you type |

### 3.1 No figures outside resolved data

Any number the agent produces before a tool returns is parametric recall. The rule covers
narration *and* persisted prose — the latter matters more, because it is saved, screenshotted
and trusted. **It is enforced in the validator** (§4.7, `Prose`), not by convention.

*(Concretely: the real 2024 US population is 340,003,797 **[measured]**. A recalled "342M"
above a tile showing the true value is worse than either alone, because the tile lends it
credibility.)*

## 4. The contract

### 4.1 Space and element

```ts
type SpaceId   = string  // "sp_" + ULID
type ElementId = string  // "el_" + ULID — SERVER-ASSIGNED

type Space = {
  id: SpaceId
  v: 1
  title: string
  elements: Element[]
  createdAt: string
  requires: string[]
  owner: string                   // a user id, never an agent — §4.10
  grants: Grant[]                 // §4.10
  budget: SpaceBudget             // §4.6
}

type Element = {
  id: ElementId
  block: string                   // "core/Choropleth"
  props: unknown                  // validated against that block's schema
  lifetime: Lifetime
  title?: string                  // human-facing, searchable — §4.11
  tags?: string[]                 // §4.11
  layout?: { span?: 1|2|3|4; minH?: "s"|"m"|"l"; group?: string }
  origin: { turn: number; at: string; by: Principal }   // §4.10 — provenance is permanent
  version: number
  invokeChainDepth: number        // server-written — §4.6
  frozen?: FrozenData
}

type Lifetime =
  | { mode: "ephemeral" }
  | { mode: "session" }
  | { mode: "persistent"; pinned?: boolean }
```

**On the lifetime count.** The brief says "persistent or temporary" — two states. This ships
three; the extra is `session`. Without it, every transient thing an agent places is either
written to the store and needs cleaning up, or dies at the end of the turn and cannot survive
the follow-up question that refers to it. If the distinction proves unused in Phase A, collapse
it: `ephemeral` and `session` differ only in when they are swept, so merging them is a one-line
change and no migration.

**Expiry is never silent.** An expiring element collapses to a stub carrying its title, its type
and a "rebuild" affordance that replays the originating query.

**Ids are server-assigned and space-scoped.** The agent emits `place()` with local placeholders
(`"$globe"`); the server assigns the ULID and returns the mapping. An agent cannot invent an id
that resolves to someone else's element.

### 4.2 Persistence: the freeze, the envelope, and the bill

A persisted element must render from data it owns. Pointing at a live third-party API is a
bookmark, not persistence.

```ts
type FrozenData = {
  at: string
  envelope: "envelope" | "slice"
  resolvedYear?: number           // a concrete year, never "mry"
  rows: unknown
  receipts: Receipt[]             // source, units, licence, attribution, and WHO froze it
  digestVersion: string
  bytes: number
}
```

**The envelope makes interaction and offline rendering compatible.** A frozen `Choropleth` still
offers tap-select and year-scrub, which need data beyond what is on screen. So freezing captures
a declared region of the query space:

- **`envelope`** (default): the whole queried `entities × range` space is cached. Every `local`
  interaction works offline, forever, within it. Stepping outside is a `refetch`, and offline
  it is **disabled with a visible reason**, not silently dead.
- **`slice`**: only displayed values are cached. Interaction offline is disabled.

Bindings follow the same rule: a frozen element's binding re-evaluates **against its own frozen
envelope**, and shows an explicit out-of-envelope state otherwise. A frozen element quietly
issuing live network calls would reintroduce exactly the drift freezing exists to stop.

**What "persist" means here, since the word has two readings.** This plan resolves *persistent*
as **the artifact and its values survive unchanged**. The other reading — a tile that keeps
itself current — is a real want and gets its own path rather than being conflated:

```ts
type RefreshPolicy = { every: "day" | "week" | "month"; keepVersions?: number }
```

`Element.refresh` re-resolves on a schedule and creates a new version. **It is not `invoke`:
no model call, no prompt, just the same query run again.** It is `[policy]` — specified here so
the distinction is in the contract, built in Phase C.

**Refresh is bounded.** Keep the last 10 versions, plus any pinned version, plus the first.
Older intermediates are compacted: spec kept, `rows` dropped, replaced by a receipt. A per-space
quota covers `FrozenData` *and* uploaded datasets together, shown in the UI, enforced on write,
priced in §8.5.

`mry` is an authoring convenience: it resolves to a concrete year at use, and the concrete year
is stored. It requires a quorum — the most recent year with ≥ *q*% of requested entities
present, default 80 — and the platform returns `{resolvedYear, coverage, excluded[]}` which the
renderer must surface.

### 4.3 The query grammar

```ts
type Query = {
  source: SourceRef
  select: string[]
  entities?: EntitySel
  range?:  { from: number; to: number } | { recent: number } | { at: number | "mry" }
  filter?: Filter[]
  order?:  { by: string; dir: "asc" | "desc" }
  limit?:  number
}

type SourceRef  = { registry: string } | { dataset: string }
type EntitySel  = { ids: string[] } | { group: string } | { all: true }
type EntityKind = "geo" | "generic"        // declared by EntityDef; see Choropleth §4.7
type Filter =
  | { field: string; op: "eq"|"neq"|"gt"|"gte"|"lt"|"lte"; value: string|number }
  | { field: string; op: "in"; value: (string|number)[] }
```

- **"Compare the G7 over time"** → `{entities:{group:"g7"}, range:{from:1990,to:2024}}`. `group`
  resolves **server-side from a versioned table**, never from model memory, so membership cannot
  vary between runs and "is the EU a G7 participant?" is settled once, visibly, in data.
- **"Worst air quality"** → `{entities:{all:true}, order:{...}, limit:10}`. The shape is
  expressible; whether a source exists is answered by `Refusal`.
- **"Sort my sales data, top 3"** → `{source:{dataset:"ds_x"}, order:{...}, limit:3}`.
- **`limit` is a query bound, not a pre-slice.** The renderer receives `limit + context` rows and
  the control stays live.

**Price basis travels with the measure, not the prose.** `MeasureDef.comparableAcrossTime`
(§2.3) is declared by the pack; when false, **the chart carries the warning**, not only the
narration. A caveat in a sentence while the misleading line sits in the persisted,
screenshot-able artifact is the wrong way round.

**`Query` is flat and tabular.** Trees, flows and networks need nodes and edges, so rather than
let diagram blocks bypass the discipline every other block follows:

```ts
type GraphQuery = {
  source: SourceRef
  nodes: { select: string[]; id: string; label?: string; group?: string }
  edges: { select: string[]; from: string; to: string; weight?: string }
  filter?: Filter[]
  limit?: { nodes?: number; edges?: number }
}
```

### 4.4 Why eight blocks

The honest answer has two parts, and only the first is an argument.

**What genuinely needs separate types: three.** `Refusal` and `Note` are not data views at all,
and a data view is the third. Everything else could in principle be one `View {query, mark}`
with `superRefine` keyed on `mark` — that gets the same validation specificity a separate
`Choropleth` type gets, natively.

**Why eight anyway: it is a taste call, and here is the taste.** Separate types put `tiers`,
`fields`, `mobile` and `a11y` where a reader can see them per block instead of as a union
keyed on a mark string, and they make the generated prompt read as a menu rather than a
parameter space. That is a legibility bet — for the model and for whoever maintains this —
not a correctness one, and if A6's eval shows the model choosing block types worse than it
chooses marks, collapsing to `View` is the indicated fix and the query grammar survives intact.

The cost is named in §8.5: the system prompt grows with every block. The encoding *within* a
block is derived rather than specified, which is where most of the single-block idea's benefit
actually lives, and that part is adopted.

### 4.5 The user's own data

```
drop a file / paste  ──▶ POST /api/datasets  ──▶ parse (csv, tsv, json, xlsx)
                                              ──▶ profile; store rows server-side
                                              ──▶ return { id, profile }

type DatasetProfile = {
  id: string; name: string; rows: number
  columns: { name: string; type: "number"|"string"|"date"|"bool";
             nulls: number; sample: unknown[]; distinct?: number }[]
}
```

**The agent sees the profile, never the rows.** A 50,000-row CSV costs ~200 tokens of profile.
`{source:{dataset:"ds_x"}}` then uses the identical query grammar, so user data is not a special
case anywhere downstream. This path needs no globe, no geo join and no third-party licensing,
which is why §8.3 ships it in week one.

### 4.6 Bindings, the snapshot, and calling the agent

```ts
type Binding = { $from: { el: ElementId; field: BoundField } }
type BoundField = "selection" | "selections" | "year" | "range" | "row" | "rows" | "sort"
```

Closed objects, never parsed strings. `selections` (plural) exists from day one — multi-select
is tried in the first minute, and adding cardinality later changes every consumer's shape.

**The snapshot**: one line per element, regenerated from live state, never appended.

```
[space] el_01J9…A2 Choropleth  sel=[BRA] camera=USA year=2023 life=persistent
        el_01J9…B7 Metric      entity←el_01J9…A2 life=persistent
        el_01J9…C1 Table       ds=ds_sales sort=region:asc limit=3 rows=412 life=session
```

Scope: **all persistent and pinned elements, plus the 12 most recently *interacted-with* session
elements**, capped at 40 lines, with `… 12 more (use find_elements)` past the cap. Recency is by
element interaction, not turn ordinal — a space is not a transcript.

**The space calls the agent.**

```ts
type Invoke = {
  on: "press" | "submit"          // NOT "interval" — see below
  prompt: string
  input?: { field: string }
  label: string                   // shown on the control; the user always knows
}

type SpaceBudget = {
  invokeCallsPerDay: number       // hard ceiling; only a user may raise it
  maxChainDepth: number           // default 2
}
```

Depth is **server-written**: `place()` issued during an invoke sets the new element's
`invokeChainDepth = placer.invokeChainDepth + 1`, and the server refuses an invoke whose element
is already at `budget.maxChainDepth`. An element cannot reset its own depth, and two elements
invoking each other terminate at the space ceiling.

Guards: **visible** (a control that will call a model says so), **depth-capped**, **budgeted**
with a ceiling only a user can raise, and **user-initiated only** (§4.10 rule 3).

**`interval` is cut from v7.** A timer that calls a model is a standing charge on a space that
may outlive anyone's interest in it, it needs a scheduler that is real infrastructure, and the
thing people actually want from it — a tile that stays current — is `RefreshPolicy` (§4.2),
which needs no model call at all. Cutting it removes 1.5 days and a class of runaway cost. If a
genuine need for agent-on-a-timer appears, it returns with the scheduler costed properly.

Failure is visible: a failed invoke leaves the element in an error state with a retry.

### 4.7 The core pack — `packs/core/blocks.ts`

The schemas, with every referenced symbol defined.

```ts
import { z } from "zod"

// ── shared vocabulary ─────────────────────────────────────────────────────
const Scale    = z.enum(["linear", "log", "quantile", "quantize"])
const Tone     = z.enum(["body", "note", "warning"])
const Emphasis = z.enum(["primary", "muted"])
const Align    = z.enum(["start", "end"])
const Iso3     = z.string().regex(/^[A-Z]{3}$/)

// ── the grammar, as zod values (z.infer<> matches the TS types in §4.3/§4.6) ──
export const FilterSchema = z.union([
  z.object({ field: z.string(), op: z.enum(["eq","neq","gt","gte","lt","lte"]),
             value: z.union([z.string(), z.number()]) }).strict(),
  z.object({ field: z.string(), op: z.literal("in"),
             value: z.array(z.union([z.string(), z.number()])).max(200) }).strict(),
])

export const EntitySelSchema = z.union([
  z.object({ ids: z.array(z.string()).min(1).max(250) }).strict(),
  z.object({ group: z.string() }).strict(),
  z.object({ all: z.literal(true) }).strict(),
])

export const SourceRefSchema = z.union([
  z.object({ registry: z.string() }).strict(),
  z.object({ dataset: z.string() }).strict(),
])

export const QuerySchema = z.object({
  source: SourceRefSchema,
  select: z.array(z.string()).min(1).max(8),
  entities: EntitySelSchema.optional(),
  range: z.union([
    z.object({ from: z.number().int(), to: z.number().int() }).strict(),
    z.object({ recent: z.number().int().positive() }).strict(),
    z.object({ at: z.union([z.number().int(), z.literal("mry")]) }).strict(),
  ]).optional(),
  filter: z.array(FilterSchema).max(8).optional(),
  order: z.object({ by: z.string(), dir: z.enum(["asc","desc"]) }).strict().optional(),
  limit: z.number().int().positive().max(1000).optional(),
}).strict()

export const BindingSchema = z.object({
  $from: z.object({
    el: z.string(),
    field: z.enum(["selection","selections","year","range","row","rows","sort"]),
  }).strict(),
}).strict()

const Bound = <T extends z.ZodTypeAny>(t: T) => z.union([t, BindingSchema])

/** THE ONE DATA SHAPE. Anything that fetches takes this. */
export const DataSource = z.object({
  query:  QuerySchema,
  freeze: z.enum(["envelope", "slice"]).default("envelope"),
}).strict()
```

```ts
// ── 1. Prose — where §3.1 is ENFORCED ─────────────────────────────────────
// Strip {{fN}} placeholders and digits bound to a word (G7, H1N1, EU27); ANY
// remaining digit is a figure the model recalled rather than resolved.
const FIG_TOKEN = /\{\{f\d+\}\}/g
const WORD_DIGIT = /(?<=[A-Za-z])\d+/g          // lookbehind: Node 10+, all modern browsers
const hasBareFigure = (s: string) =>
  /\d/.test(s.replace(FIG_TOKEN, "").replace(WORD_DIGIT, ""))

export const Prose = z.object({
  text: z.string().max(4000).refine(s => !hasBareFigure(s), {
    message: "Prose.text may not contain figures. Move each number into figures[] and reference it as {{f0}}.",
  }),
  figures: z.array(z.object({ ref: BindingSchema, format: z.string().optional() }).strict())
           .max(12).default([]),
  tone: Tone.default("body"),
}).strict()
// [measured 2026-09-19, Node] rejects "a 5% rise", "$100", "in 2024", "top 3",
// "340,003,797"; accepts "the G7", "H1N1", "EU27", "it is {{f0}} people".
```

### 4.8 Tool definitions

One discriminated `place` over the block union, not eight tools.

```ts
place   ({ name, block, props, lifetime?, layout?, title?, tags? })
update  ({ el, props?, lifetime?, title?, tags? })
remove  ({ el })
duplicate ({ el, overrides? })          // §4.11 — "same chart, different countries"
group   ({ els: ElementId[], title })   // §4.11
query   ({ ...Query })                  // returns a digest, never rows
find_elements ({ text?, tags?, block?, before?, after? })   // §4.11
```

`place.props` validates against `block`'s schema after the discriminator is read. This shape is
what A1's strict-mode spike must test: `strict: true` over a discriminated union of eight
schemas is exactly where provider grammar support tends to break.

### 4.9 Prop rules

1. **Data-shaped, not pixel-shaped.** No `width`, `margin`, `className`. *Admitted exception:*
   `align` on table columns.
2. **Flat, except per-column and per-series descriptors.**
3. **Enums over free strings.** *Admitted exception:* `iso3`, regex-validated and checked
   against the geo table.
4. **≤8 props, ≤3 required.** `Table` and `Chart` are exempt and documented.
5. **Everything optional renders.** A half-streamed spec must draw something.
6. **`settled`:** a block is settled when the tool call that produced it closes, **or** after
   400 ms with no new patch. A settling element **reserves its declared `minH` from mount**, so
   resolving it never shoves what is below it down the page.
7. **Mobile behaviour is declared per block** in `BlockDef.mobile`.

### 4.10 Who may write to a space

A space that accumulates, outlives a session, opens by link and can be written to by "some
other API/AI agent" has an authorisation problem a transcript never had.

```ts
type Principal =
  | { kind: "user";  id: string }
  | { kind: "agent"; id: string; onBehalfOf: string }
  | { kind: "link";  token: string }

type Grant = {
  principal: Principal
  role: "owner" | "editor" | "agent" | "viewer"
  packs?: string[]                // an agent may be restricted to named packs
  expiresAt?: string
}
```

| | owner | editor | agent | viewer |
|---|---|---|---|---|
| read | ✓ | ✓ | ✓ | ✓ |
| `place` / `update` | ✓ | ✓ | ✓ | — |
| `remove` | ✓ | ✓ | own elements only | — |
| `promote` to persistent | ✓ | ✓ | ✓ (counts against quota) | — |
| trigger `invoke` | ✓ | ✓ | — | — |
| raise `SpaceBudget`, grant access | ✓ | — | — | — |

Four rules:

1. **An agent never acts on its own behalf.** `onBehalfOf` is mandatory and lands in
   `origin.by` and in `FrozenData.receipts`. "Which agent placed this, for whom" is answerable
   for every element, forever.
2. **An agent cannot raise a budget or grant access.** A confused or compromised agent can
   exhaust a budget but cannot enlarge one, and cannot invite another agent in.
3. **An agent cannot trigger `invoke`** — only a user action fires it. Otherwise an agent places
   an element that calls an agent, which is a loop with a budget attached rather than a depth
   cap. `invokeChainDepth` bounds chains a human started; this rule stops one starting itself.
4. **A link grant is `viewer` and cannot be upgraded.**

**Multi-agent is what the brief asked for.** `Grant.packs` is how it stays sane: a specialist
agent gets `packs: ["core","acme-crm"]` and cannot place a block outside them — the validator
rejects it before any renderer runs. A non-Claude agent is just a `Principal` with a narrower
grant, which is also what gives §8.7's second-provider test a shape.

**Conflicts** are last-write-wins on `Element.version`; the loser's write is rejected and
returned for retry. No merge — elements are small and independently placed, so a real conflict
means two agents were told to do the same job, which is an orchestration bug worth surfacing.

### 4.11 Finding things in a space that has grown

A space that accumulates for a year needs more than a layout `span`. The honest position:

**Phase A ships nothing here** beyond `title` and `tags` on `Element` — because they must exist
from the first write or they cannot be backfilled for elements already placed.

**Phase B ships `find_elements`** (text over title/tags/receipts, filtered by block type and
date), `duplicate`, `group`, and collapse/archive for `persistent` elements. These answer
"find the map I made a few weeks ago about Brazil", "same chart, different countries" and
"group these five together" — none of which v6 could express.

**Explicitly deferred:** spatial canvas layout (free positioning, zoom-out overview), nested
groups, and cross-space search. A space is a vertical ordered list with groups until there is
evidence that is not enough. **[policy]**

## 5. Assets

The brief names "free sprites, ui elements, pixel art, painting software, mesh/model software"
and asks for things made ourselves where possible. This is what makes output look like one
designed product rather than a chart library with a dark mode.

### 5.1 What ships, and how a licence is established

**[measured 2026-09-19, npm registry]**

| Pack | Version | Licence | Verdict |
|---|---|---|---|
| `lucide` | 1.47.0 | **ISC** | **Ship.** Permissive, no attribution burden, one visual system. |
| `material-symbols` | 0.47.4 | **Apache-2.0** | **Ship** as the fallback set. |
| `@fontsource/inter` | 5.3.0 | **OFL-1.1** | Ship. Self-hosting is distribution → `licenses/` build step. |
| `openmoji` | 17.0.0 | **CC-BY-SA-4.0** | **Not in core.** |

**OpenMoji is the share-alike trap.** Copyleft propagates: CC-BY-SA art inside a themed pack
puts an obligation on the pack, and every downstream commercial user inherits it. Optional pack
flagged `shareAlike: true`, or it does not ship. The same test cut Open-Meteo (Appendix A). It
is a standing rule applied before adoption.

**Sprites and pixel art — a method, because the claim could not be verified remotely.**
**[measured 2026-09-19]** game-icons.net states **CC BY 3.0** on its own about page.
**Kenney could not be machine-verified**: `kenney.nl/assets` returns HTTP 200 but the licence
text is JS-rendered, `kenney.nl/license` 404s, Kenney's own GitHub repos carry **MIT** (the
starter kits), and a third-party mirror carries **CC0-1.0**. Widely-repeated CC0 is not
evidence.

So the rule is a method, not a guess: **the authoritative licence for an art pack is the licence
file shipped inside the pack you actually downloaded**, pinned by checksum. The audit records
`{spdx, attribution, commercialUse, sha256}` per pack, and CI fails any asset with no recorded
licence — the same gate Appendix A applies to data. Until that audit runs, **sprite sourcing is
the least-verified claim in this document.**

### 5.2 What an asset pack contains

```ts
type AssetPackDef = {
  id: string
  licence: { spdx: string; attribution: string; commercialUse: boolean; sha256: string }
  shareAlike?: boolean            // true ⇒ never in core, never bundled by default
  kinds: {
    icon?:   { names: string[]; format: "svg"; grid: 16|20|24 }
    sprite?: { names: string[]; format: "png"; size: number; palette: string[] }  // §5.3
    texture?:{ names: string[]; format: "png"; tileable: boolean }
  }
}

type AssetRef = { pack: string; name: string; v?: string }
```

`AssetRef` is never a URL and never a path — the same closed-reference rule as `source`, for
the same injection reason. An unknown asset resolves to a labelled placeholder.

**How a model picks an asset.** Not by browsing a list of 1,500 icon names in the system
prompt — that would dominate the token budget (§8.5). Assets are addressed through **semantic
roles** declared by the pack: `{pack:"core", name:"trend-up"}` resolves through a role map, and
the prompt carries roles (~40) rather than names. An unmapped name still works for a human
author; the model is steered to the small set.

### 5.3 "On theme" is a recolour pipeline, not a generator

**Do not plan to generate sprites.** On-theme pixel art at consistent quality is not a week of
work and does not belong on the critical path of a project whose thesis is elsewhere.

**A build-time recolour pass** captures most of the value: art is sourced or authored in a flat
indexed palette; `tokens.json` maps palette slots to theme ramps; the emitter produces a variant
per theme. Flip the token file and the sprites change with the CSS — which is what makes §8.6's
theme demo more than a palette swap, and it is the same single-source-of-truth argument as
§5.4, extended to art.

**Authoring, since the brief names painting software:** **Aseprite** for pixel art — indexed
palettes and palette swapping are native to it, which is exactly what the pipeline consumes —
and **Inkscape** for SVG chrome. Both export the indexed formats the pipeline wants; neither
puts a licence obligation on output. A recommendation, not a dependency: the pipeline's input is
an indexed PNG or an SVG, whatever drew it.

**3D and meshes are deferred, explicitly.** A 3D tier means a format decision (glTF), a renderer
that is not the SVG/DOM one, a licence surface, and an accessibility story with no good answer.
It is a second product. Deferred with reasons — and §1.2's persistence argument is *stronger*
for a 3D scene than for a chart, so it is a real future direction rather than a polite no.

### 5.4 Tokens

Source of truth is `tokens.json` (DTCG-shaped), **not a CSS file** — CSS custom properties never
reach a canvas `fillStyle`. Emitters produce `theme.css`, `tokens.ts`, a GPT-Vis/G2 theme object,
and the sprite palette maps. Ramps authored in OKLCH so light and dark derive from one
definition; separate categorical data palette, contrast-validated in **both** themes.

**Bounded honestly:** one token source generating CSS variables, a G2 theme object, a validated
palette and the sprite recolours is about a week. **"A canvas chart and a DOM card look
pixel-identical" is not deliverable** and is not claimed: canvas has no CSS cascade, and G2
re-derives ramps through d3-color in sRGB, voiding OKLCH evenness exactly at the choropleth
legend. What breaks first and most visibly is the **dark-mode toggle** — CSS flips instantly
while canvas lags, through a different API. Budget a runtime theme-push on `matchMedia`.

## 6. The spatial block, and the data layer

*World Bank specifics — the measured digest failures, the licensing findings and the resolver's
error taxonomy — are in **Appendix A**. They are pack detail, and the clarification is explicit
that the statistics browser was never the product.*

### 6.1 `d3.geoOrthographic`, not WebGL

A drag handler updating `.rotate([λ, φ])` gives a spinnable globe from the *same* `d3-geo` and
the *same* topojson already loaded.

**Measured sizes** (esbuild + gzip -9; bundlephobia reports a broken 709 B for `d3-geo`):
`d3-geo` alone **14.7 KB gz**; the realistic day-1 set (`d3-geo` + `topojson-client` + `d3-scale`
+ `d3-scale-chromatic`) **17.8 KB gz**; plus `world-atlas` 110m at **38.4 KB gz**. **~56 KB
against ~600 KB.**

Deleted from the critical path: a ~559 KB gz / 2.0 MB parsed bundle; `h3-js` (213 KB, for a
hexbin layer never used); a static `three/webgpu` import (2.28 MB) whose tree-shaking is a coin
flip; three copies of three.js failing as silent `instanceof` errors; and **`globe.gl` reading
`window.THREE` at module scope, which throws in Node** and would have forced `dynamic(ssr:false)`,
keeping the globe out of the server-streamed paint.

**Scoped honestly.** "~30 lines" is the *rotate handler*. Canvas hit-testing, the fill scale, the
legend, the halo channel, `settled` and the mobile scroll rules are not in it. **The block is ~3
days; with the camera table (§6.2) and the year-scrub and pinch handling, A4 is 4 days** (§8.3).
**"60fps on a phone at 177 polygons" is [asserted]** — the one performance number in a document
that measures everything else — and A4 measures it on a real mid-range device.

### 6.2 The country-code join

`world-atlas` features carry only `{name}` in `properties`, but **their `id` is the ISO-3166-1
numeric code** as a zero-padded string (`"840"`, `"250"`). Missing that is what prices this job
in days instead of an hour.

**[measured]** `numericToAlpha3` resolves **174 / 177**. Joined to the live World Bank list
(`region.id !== 'NA'` → 217 countries): **169 / 174**. **Total hand-adjudication: one override
(Kosovo → `XKX`).** Generated at build time and vendored: **175 entries, 902 bytes gzipped.**

**The exclusion list, as one list:** N. Cyprus, Somaliland, Kosovo *(no `id` in world-atlas)*;
W. Sahara, Falklands, Fr. S. Antarctic, Taiwan, Antarctica *(valid ISO code, no World Bank row)*.
Eight of 177. The CI test is ~15 lines.

**Stay on 110m.** 50m is 230 KB gz *and makes the join worse*: five no-id features plus a
duplicate id `036` shared by Australia and Ashmore & Cartier, so `new Map(...)` silently drops
Australia.

**`focus` needs a vendored camera table — ~half a day**, counted in A4. Computed centroids fail:
`geoCentroid(France)` is open ocean off Portugal (French Guiana drags it); `geoBounds` on Russia
and Fiji returns `maxLon < minLon` across the antimeridian; the USA's bounds span 105° because of
the Aleutians. ~40 entries, generated once, hand-corrected.

**Disputed boundaries are data, not contract.** Natural Earth encodes editorial choices on
Kashmir, Crimea, Taiwan and Western Sahara. `entities:"countries"` stays defined by World Bank's
own `region.id !== 'NA'`, and territory policy lives in **versioned geo data with an override
map** — never a `"sovereign"` enum in a block schema, which would force every conforming renderer
to agree on a list of sovereigns in order to be conformant.

**Mobile rules, in `BlockDef.mobile`:** wheel never zooms; globe ≤55vh so there is always a
scroll gutter; below 600px a one-finger drag must not steal page scroll. Pinch zooms.

### 6.3 `digest()` — the shape, and why the naive one launders errors

The model never sees rows. It calls `digest()` and narrates from that. The naive nine-field
version `{min,max,first,last,delta,cagr,units,n,outliers}` is actively dangerous: it truncates
silently under default pagination, cannot populate `units`, cannot represent nominal-versus-real,
and hides gaps behind `n`. Each of those is measured against the live API in **Appendix A**.

A digest that cannot say "this number is not comparable across time" is not a safety mechanism.
It is a laundering mechanism: it converts the model's uncertainty into a structured,
authoritative-looking object.

```ts
{ first: {year, value}, last: {year, value}, min, max,
  n, nMissing, gaps: [[y, y]],
  cagr, priceBasis, currency, comparableAcrossTime,   // ← declared in MeasureDef (§2.3)
  units, unitsSource,
  series12: [...],        // ≤12-point resample — closes the whole
                          // "when did X happen / who overtook whom" class
  caveats: string[] }
```

**This is platform code over normalised rows (§2.3)**, so every pack gets it — which is the
whole reason resolvers were kept declarative.

### 6.4 The resolver

**Server-side.** Not for CORS but because rate limits would be charged against each end user's
IP, browsers cannot set the `User-Agent` some sources' policies require, and there is no
cross-user cache. Its work: pagination, aggregate filtering, cache keying with the resolver
version in the key, single-flight dedup, and **a monotonic request token per element** so
tapping Brazil-then-China quickly cannot leave Brazil's data under China's label.

**Abort tokens ship in Phase A** — a counter and a comparison, and deferring them guarantees the
mislabelled-data bug is live during the exact period anyone is watching.

## 7. Safety

Security behaviours here are **[asserted]** — design intent, not measured. They are tested in
A1 and B4; until then they are the one part of this document not backed by a check, and saying
so is the point of the labelling discipline.

**7.1 Rendering.** `Prose` renders markdown through a named sanitizer, no raw HTML. Images
resolve through the asset registry or an allowlist proxy. No prop accepts an arbitrary URL
scheme.

**7.2 References are closed.** `source` is a registry key, `AssetRef` is a pack/name pair,
bindings are closed objects. One rule covering three surfaces.

**7.3 Third-party resolver packs.** Resolvers are data (§2.3), so RCE is out of scope by
construction. The risks that remain, and are *not* solved by that:

- **Exfiltration through slots.** A resolver author controls which `Query` fields fill their
  request. **Only `select`, `entities` and `range` may fill slots** — `select` validated against
  the pack's declared `measures`, `entities` against its declared entity table, `range` numeric.
  **`filter` never reaches a third-party request**; filtering on free text happens platform-side
  after fetch. This costs a round trip on some queries and removes free-text egress entirely.
- **SSRF via DNS and redirects.** `base` is allowlisted at install. At request time the host is
  resolved, the address is checked against the blocklist (RFC1918, link-local, `169.254.0.0/16`,
  loopback, ULA), and **the connection is pinned to that checked address** — a second lookup
  would still be rebindable. **Redirects are not followed.** A 3xx from an allowlisted host is an
  error, because following one is the standard way an allowlist is bypassed.
- **Expression evaluation in path extraction.** `response` paths use a **restricted subset
  implemented in-house** — member access, array index, wildcard — with **no filter or script
  expressions** (`?()`, `()`). General JSONPath libraries differ in whether those evaluate code,
  and the safe move is not to depend on which one was installed.

**7.4 Third-party block packs are code**, because `render` is a function. There is therefore **no
open block registry** (§2.4): packs are first-party or vendored, installed at npm-dependency
trust level. A renderer sandbox — defining what `ctx` exposes, and isolating untrusted render
code — is the prerequisite for opening it, and it is out of scope here rather than waved at.
This is the asymmetry: resolvers got a security design because they can be opened; blocks got a
scope boundary because they cannot, yet.

**7.5 Uploads and invoke.** Datasets: size caps, parser timeout, type sniffing rather than
trusting the extension, per-space quota shared with `FrozenData`, formula stripping on xlsx
ingest, never cross-readable between spaces. Invoke: server-side depth counting, a budget only a
user can raise, user-initiated only (§4.10), and no user free-text reaching a prompt without the
validation a turn gets.

**7.6 Accessibility is a requirement.** It is the most expensive retrofit and the one that blocks
shipping commercially, so `a11y` is a **required field in `BlockDef`** — a block without a role
and a keyboard path does not register.

- **SVG/DOM is the default substrate**; canvas is an optimisation adopted only where measured,
  always with a DOM shadow tree carrying the same data.
- The globe: arrow keys rotate, `Tab` cycles countries in fill order, `Enter` selects.
- Every data block exposes a **table view of its own data**, doubling as copy/export.
- The conformance suite runs axe; the static-SVG renderer makes "what does this element *say*"
  mechanically answerable.

**A3 is split** because a Postgres schema with migrations and quota accounting is a different
job from a space shell, and bundling them hid a day — the same reasoning that split A5 from A6.
**A4 is 4 days, not 3**: §6.1 prices the block alone at ~3 and §6.2 adds the camera table at ~½,
before scrub, pinch and the measurement pass.

**The eval harness is in Phase A.** The prompt is generated from the schemas, so every schema
change rewrites it and invalidates every prior result. A plan that measures its thesis once and
then keeps changing the thing being measured has the detector switched off.

**The v0 is A0–A3b plus A6 — about 8 days.** That is the smallest thing that answers "does this
work at all", and §1.4 means it before the rest is built.

### 8.4 Phase B — every week ships something visible (~5 weeks)

| Week | Ships (visible) | Carries (invisible) |
|---|---|---|

| B5 | Full resolver: pagination, aggregates, cache, attribution, nightly live-drift job | recorded fixtures |

**B4 proves disposability, not extensibility** — same product, same blocks, rendered
differently. That is a real conformance proof and it is all it is.

**The extensibility test is B6, and it is honest about staffing.** With a team of one there is
no second author, so the test is: **build `packs-geo` using only the published `defineBlock` /
`defineResolver` docs and a frozen `registry` package — no edits to core.** Budget **2 days**.
**Kill criterion: zero changes to `packages/registry` or `packages/protocol` are required.** If
core has to change to admit its own second pack, the extension API is not one, and §2's central
claim fails. That is a weaker test than an external author and the document does not pretend
otherwise — it is the strongest test one person can actually run.

### 8.5 What it costs

**Tokens** **[asserted — arithmetic over stated budgets, measured in A6]:**

| Item | Tokens |
|---|---|
| System prompt (8 blocks + query grammar + ~40 asset roles + capabilities) | ~2,000–3,000 |
| Space snapshot at the 40-line cap | ~600 |
| One `place()` spec | ~250 |
| One digest with `series12` | ~400 |
| **Turn 10, input** | **~4,000–5,000** |

The system prompt grows with every block — the real scaling cost, and the reason the core pack
is 8, extensions are per-app, and assets are addressed by ~40 roles rather than 1,500 names
(§5.2). The snapshot cap matters for the same reason: without it a long-lived space makes every
turn more expensive forever, which is uniquely bad for a product selling long-lived spaces.

**Storage** **[asserted]:** a frozen `Choropleth` envelope over 217 entities × 35 years of one
measure is ~7,600 values — ~**120 KB** as JSON, less compressed. Ten retained versions is ~1.2 MB
per element; a space with 20 such elements is **~24 MB**. Object storage at that size is cents
per space per year. The cost that bites is unbounded version growth, which is why §4.2 bounds it.

### 8.6 Done looks like

A stranger opens a space, drops in a CSV, gets a sortable table. They ask about America, get
prose immediately and a globe they can drag, tap Brazil, scrub the year — no model calls. They
close the tab, come back the next day, and **it is all still there**, rendering from frozen data,
showing the same numbers. They pin one element, let another expire and watch it leave a stub
rather than vanish. They flip one token file and the identical space re-renders as a visibly
different product, sprites and all.

Then the part that is not rehearsed: the skeptic types three prompts of their own, one
deliberately out of vocabulary, and the system says precisely what it cannot do instead of
bluffing.

**But the film is not the proof, and the distinction matters** because a recording cannot
distinguish a generated spec from a fixture — especially in a codebase that contains fixture
replay. **The falsifiable claim is A6's:** 20 prompts × 3 samples, ≥80% block-type match, zero
invalid measure ids, zero unrefused out-of-vocabulary prompts, threshold written before running.
If the recording exists and A6's numbers hold, the thesis is proven. If only the recording
exists, a globe is proven.

### 8.7 Stated non-goals

- **A non-Claude agent writing into a space it did not build.** Nothing here is verified against
  a second provider beyond A1's portability spike. §4.10 gives it a shape — a `Principal` with a
  narrower `packs` grant — and B6 tests the registry it would use, but the integration itself is
  not Phase A work.
- **An open block registry** — requires the renderer sandbox (§7.4).
- **A code-backed resolver tier** (§2.3).
- **`interval` agent timers** (§4.6) — `RefreshPolicy` covers the real want.
- **3D/meshes** (§5.3), **sub-national geography**, **a geocoder**, **spatial canvas layout**
  (§4.11).

## 9. Glossary

**block** — a named, schema-validated element type in a pack (`core/Choropleth`).
**digest** — the platform's statistical summary of resolved rows; what the agent sees instead of
data (§6.3).
**element** — one thing in a space: a block name, validated props, a lifetime, an id.
**envelope** — the region of a query's space cached when an element is frozen, within which
interaction keeps working offline (§4.2).
**freeze** — writing resolved values into an element on promotion to persistent, so it renders
from data it owns (§4.2).
**invoke** — an element's own control calling an agent; budgeted, depth-capped, user-initiated
(§4.6).
**mark** — a one-word hint (`line|bar|area|point`); encoding is otherwise derived from data shape.
**pack** — a versioned bundle of blocks, resolvers and assets (`core@1`).
**principal** — who is acting: a user, an agent acting for a user, or a link token (§4.10).
**query** — the closed grammar describing what data an element wants (§4.3).
**resolver** — a declarative descriptor of how to fetch from one source; data, not code (§2.3).
**space** — the durable surface that accumulates elements.
**tier** — what an interaction costs: local, refetch, invoke, turn (§3).

## Appendix A — the World Bank pack in detail

Pack detail, kept out of the main document because the statistics browser is one demo, not the
product. Every figure here is **[measured against the live API, independently re-verified by two
reviewers, 2026-09-19]**.

**Why the naive digest is dangerous:**

- **It truncates silently.** Default `per_page` is **50**. A BRA+USA 1990–2024 call has
  `total=70`, returns 50, and the USA's present years become **exactly 2010–2024** — so `first`
  is 2010, not 1990, and `delta` spans 14 years instead of 34. Well-formed object, wrong numbers,
  HTTP 200 throughout.
- **`units` cannot be scraped.** The `unit` field is an **empty string** on both the observation
  and the indicator metadata. This is why `MeasureDef.units` is *declared* (§2.3) rather than
  fetched — it removes a second HTTP call the declarative resolver could not have made anyway.
- **Nominal versus real is unrepresentable.** Brazil's GDP CAGR is **5.24%** current US$ and
  **2.36%** constant 2015 US$. The series shows a 44% "collapse" 2011→2020 that is almost
  entirely currency depreciation. `outliers` makes it worse: those years are FX artifacts, and
  flagging them invites the model to narrate them as economic events.
- **`n` hides gaps.** Syria 1990–2024 has 2 nulls. Two series with `n:33` can be consecutive or
  war-shaped, and the model draws a trend line through the hole.

**First-class measures:** `NY.GDP.MKTP.KD` (constant) and `NY.GDP.PCAP.CD` (per capita) — per
capita is usually the honest answer to "why is it behind" ($10.3k vs $86k), and the naive digest
pushes the model toward the wrong comparison.

**Error taxonomy:** a bad indicator returns **HTTP 200 with an error envelope**; the genuinely
silent case is a *valid* code with no data → `value: null`. Aggregate filtering needs
`region.id !== 'NA'`, or `/country/all` returns World (8.14B), IDA & IBRD total and Low & middle
income as the top three, putting every real country in the bottom 17% of the ramp — a flat
monochrome ball.

**Licensing, all verified:** World Bank **CC-BY**, attribution propagates to every rendered chart
and into `FrozenData.receipts`. **Open-Meteo's free tier is non-commercial only — cut from
defaults**, or every downstream commercial user inherits a ToS breach. **Wikipedia is
client-impossible** (the `User-Agent` its policy requires cannot be set in a browser) and
CC BY-SA share-alike. REST Countries is an unmaintained single point of failure — vendor a
snapshot. Every `ResolverDef` carries `licence`; CI fails one without an attribution string and
generates `THIRD_PARTY_DATA.md`.
