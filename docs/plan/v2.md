# Orrery — Plan v2
*(working name; "Auto-UI" collides with "A2UI" when spoken. User's call.)*

## 0. The acceptance test, written first

Everything below exists to make this exact trace work. If it can't be hand-written today,
the block API isn't designed.

```
USER: show me america

(phase 1, streamed as text, arrives in ~400ms)
  "Here's the United States — 342M people, $29.2T GDP. Drag to spin it,
   click any country to compare."

(phase 2, tool call `render_blocks`, ~250 tokens)
{ "v": 1, "blocks": [
  { "id": "b1", "type": "Globe",
    "focus": "USA", "highlight": ["USA"], "spin": "drag",
    "choropleth": { "source": "worldbank:SP.POP.TOTL", "year": 2024 } },
  { "id": "b2", "type": "Metric", "group": [
    { "label": "Population", "ref": "worldbank:SP.POP.TOTL@USA/2024" },
    { "label": "GDP",        "ref": "worldbank:NY.GDP.MKTP.CD@USA/2024" } ] } ] }

(frame) narration, then a globe centred on N. America with the US lit,
        two metric tiles beneath it. Total ~2.4s to first paint.

(drag)  rotates. 0 model calls. 0 network.
(click BRA) b2 re-resolves to Brazil. 1 cached HTTP call. 0 model calls.
        A note is appended to the transcript: `[ui] globe: selected BRA`

USER: why is it so far behind?
  -> model has "selected BRA" in context, calls digest("worldbank:NY.GDP.MKTP.CD",
     ["BRA","USA"], 1990..2024) -> {first, last, delta, cagr, units, n}
     -> narrates accurately over data it never fully saw.
```

That last step is the whole thesis in one line: **the model narrates from a digest, the
block renders from the full series, and the numbers never enter the token stream.**

## 1. What is already built (verified Sept 2026 — do not rebuild)

| Project | License | Owns |
|---|---|---|
| **Vercel `json-render`** v0.21.0, 16.4k★ | Apache-2.0 | Catalog/registry, `{root,elements}` tree, RFC-6902 patch streaming, expressions, 12+ renderers (React, Vue, Svelte, Solid, RN, **Ink/terminal**, PDF, email, R3F). **`catalog.prompt()` already generates the system prompt from schemas.** 36 shadcn components. |
| **Google A2UI** v0.9.1 | Apache-2.0 | Wire standard **+ a client-held catalog concept**. 15 chrome components. Zero viz. Its own docs name "a custom component containing an interactive chart / Google Maps" as *what you must supply*. |
| **AntV `GPT-Vis`** | MIT | 26 LLM-targeted chart types — the entire quantitative tier **and** the entire relational tier (mindmap, network, flow, org chart, fishbone, indented tree). LLM-friendly DSL, MCP server, 3 themes, **streaming render, fault-tolerant partial data.** |
| **MCP Apps** (SEP-1865), stabilized Jan 2026 | — | Host↔server interactive UI, **including standardized CSS custom properties for host theming.** |
| **Thesys C1** | paid SaaS | Proof of demand, not a competitor to a library. |

**Consequences, stated plainly:**
- Do not build an element tree. json-render owns it.
- Do not build a prompt generator as a headline feature. `catalog.prompt()` exists.
- Do not build charts or diagrams from scratch. GPT-Vis has them, MIT, already streaming.
- "Model emits declarative chart JSON, runtime renders" is a **solved, published pattern**
  (Vega-Lite, NL4DV, ChartGPT). Claiming novelty there is not survivable.

## 2. The gap, honestly: two items, not five

v1 claimed five. Three are occupied. What is genuinely unbuilt:

1. **A spatial tier a language model can parameterise.** Nobody in generative UI ships
   `Globe` / `Region` / choropleth as an LLM-fillable block. This is where the user's own
   example lives and it is empty.
2. **Data-by-reference with a digest tool.** json-render has `$state` bindings but no
   dataset resolver; GPT-Vis takes literal data. A model that *names* a dataset, gets a
   statistical digest to narrate from, and never sees the rows — that is unoccupied, and
   it is the harder one to copy because it is a licensing + ops problem, not a code one.

Secondary, real but not a moat: **one token system that themes both our blocks and the
borrowed ones**, so a GPT-Vis chart and our globe look like one product.

> Anything Vercel could ship as `@json-render/charts` next month is not our moat.
> Ship the moat first.

## 3. Layering — and what "disposable" actually means

v1's rule was "nothing above the line imports React." That is a *syntactic* check being
sold as an *architectural* guarantee. A lint rule cannot make anything disposable.

**The contract is four things:** block prop schemas · the action/escalation vocabulary ·
the token semantics · the resolver protocol. Everything else is an implementation.

```
CONTRACT (durable — this is the repo's reason to exist)
  @orrery/contract   zod only   block prop schemas, action vocab, data-ref type,
                                version field + migrations/
  @orrery/tokens     zero deps  OKLCH source -> theme.css + tokens.ts + GPT-Vis palette
  @orrery/resolve    SERVER     dataset resolvers, digest tool, cache, attribution meta

IMPLEMENTATION (replaceable — expected to be replaced)
  @orrery/react            our blocks, incl. the Globe
  @orrery/catalog-json-render   registers our blocks as a json-render catalog  <-- ships slice 1
  apps/playground          a json-render app
```

Two rules, both cheap, both enforced:
- **Import rule** (kept from v1, it costs nothing): contract packages import no React, no
  DOM, no render lib. Preserves optionality.
- **Conformance suite** (new, and this is the one that matters): ~40 frozen specs that any
  renderer must satisfy. Disposability is proven by *a second renderer passing the suite*,
  not by an import graph. The cheap proof: json-render already ships an **Ink (terminal)**
  renderer — implement `Metric` + `Table` + `Prose` for the terminal in ~150 lines. A
  terminal globe is absurd, which is exactly why it's a good test of where the contract
  leaks.

**Wording fix:** v1's diagram put durable packages at the *top* and its prose said "throw
away the top half." Here, **the bottom half is the disposable half.**

## 4. The catalog — 6 blocks in slice 1

`Globe` · `Region` · `Prose` · `Metric` · `Table` · `Chart`
(plus `Stack`, which is 30 lines and barely a block)

Cut from v1's 24: every input block (`Form`/`Slider`/`Choice` — app chrome, the exact
commodity §1 identifies), `Map` (needs a geocoder; none was listed — vendor a country/state
bbox table instead and let `Region` cover it), `Progress` (a `Metric` with a bar), the
whole relational tier (defer to a GPT-Vis adapter), `theme-gen`, both protocol bridges
beyond json-render.

### Prop rules — written as they will actually be enforced

v1's rules were aspirational; `Table` violated three of six *in slice 1*. Restated:

1. **Data-shaped, not pixel-shaped.** No `width`, `margin`, `className`. Color only via
   semantic enums (`emphasis`, `severity`). **Exception, admitted:** `align` on table
   columns — numbers right-align, and the model knows the column is numeric before the
   theme does.
2. **Flat, except per-column/per-series descriptors.** `Table.columns` is a nested array.
   That's irreducible; TanStack Table is headless *because* tables are.
3. **Enums over free strings**, always.
4. **≤8 props, ≤3 required** — for display blocks. `Table` is exempted and documented.
5. **Two schemas per block, one source.** `BlockStrict` (required props; drives `tool.json`
   and eval) and `BlockPartial` (mechanically derived, all-optional; drives streaming).
   v1 asserted `strict:true` *and* "everything optional renders" — those are mutually
   exclusive. CI asserts `BlockPartial` is derived, never hand-edited.
6. **`settled` signal.** Layout-computed blocks render a skeleton until their props stop
   changing, then lay out once. Removes streaming jitter as a class.
7. **Mobile is a constraint now**, at 6 blocks, not at 24. Every block declares its
   behaviour at 390px.

### Data by reference — with the hole in v1 closed

v1's version blinds the model: it writes prose about data it never saw, next to a chart
showing the real numbers. **Confidently wrong narration lent credibility by a correct
chart is worse than a hallucinated number.** Three fixes:

- **`digest` is a tool the model calls** before narrating: returns
  `{min, max, first, last, delta, cagr, units, n, outliers}`. Tens of tokens; enough to
  narrate correctly and to choose log-vs-linear.
- **Hybrid:** <50 data points go inline as literals; above that, by reference.
- **Unknown codes reject with a suggestion.** The World Bank API returns `200` + empty
  array for a bad indicator — it fails *silently*. The resolver validates against a
  bundled index and says "did you mean `NY.GDP.MKTP.CD`?"

## 5. Interaction — three tiers, plus the thing v1 forgot

Tiers as v1 (local / refetch / escalate; local is the default, blocks declare escalation
**in the schema**, above the line). The omission:

**State echo.** Every tier-1 interaction appends one compact line to the transcript:
`[ui] globe: selected BRA` · `[ui] table: sorted emissions desc`. Without it, "why is that
one so high?" is undefined behaviour — the user is looking at state the model cannot see.
Costs ~8 tokens. It is the entire difference between a widget and a conversation.

**Turn semantics.** Blocks carry stable IDs. Turn N+1 may patch turn N's block by ID.
Earlier blocks stay mounted and stay interactive. Decided now because it determines
whether specs need IDs — they do.

**Prose/UI interleaving: two-phase.** The model streams narration as text, *then* emits the
tool call. One-phase (a `Prose` block inside the spec) means the user stares at a spinner
and then gets a silent widget — the opposite of the reference product.

## 6. Cost — reframed, because v1's argument was false

v1 claimed ~150-400 output tokens vs 2000-4000 of React, caching makes the prefix free,
Haiku 4.5 suffices. Three problems:

- **The caching claim was self-defeating.** Haiku 4.5's minimum cacheable prefix is
  **4,096 tokens**; v1's CI rule *capped the catalog at 2,500*. Below the minimum nothing
  caches **and no error is returned** — you'd pay full price forever and never know.
- **The baseline was a strawman.** Production assistants emit markdown (~200-600 tokens),
  not React. Against the real default, a block spec costs *about the same or slightly more*.
- **"150-400 tokens" excluded the narration and inline table rows.** Realistic multi-block
  responses are 400-900.

**Honest claim, which is enough:** *a block spec costs about what the text reply it
replaces costs, and data-by-reference removes the numbers from the token stream entirely.*
Justify on quality, not price.

Decisions: **Sonnet 5 for block selection in slice 1** (1,024-token cache minimum, fits a
real catalog). Send the vocabulary **once** — `tool.json` in the `tools` block, since that
is what `strict:true` constrains; `catalog.md` carries heuristics and few-shot only.
Version the tools block, because any tool-definition change invalidates the entire cache
hierarchy for every user. CI asserts `cache_read_input_tokens > 0` on the second eval call,
since cache failure is otherwise silent.

**Day-1 spike, before anything depends on it:** `strict:true` does **not** support
`oneOf` + `discriminator`, recursion, `pattern`, or min/max. `Chart.kind` is a discriminated
union. Run it through the Zod→JSON-Schema emitter on day one and record the result;
`additionalProperties:false` everywhere as a schema-gen invariant.

## 7. Parts — corrected

| Need | Pick | License | Note |
|---|---|---|---|
| Globe | **`globe.gl`/`three-globe`** + `world-atlas` + `d3-geo` | MIT / PD / ISC | **cobe cannot do this.** It draws a dot cloud with pin markers — no polygon layer, no per-country picking, no choropleth. "Show me America" on cobe is a dotted sphere with a pin near Kansas. Costs ~600KB of three.js; pay it. |
| Charts | **spike: GPT-Vis adapter vs Recharts** | MIT | GPT-Vis already has streaming + partial-data tolerance. Recharts is ~130KB gzipped and bundles d3. Decide day 1 behind an adapter either way. |
| Tables | TanStack Table (headless) | MIT | Verified — **no relicensing event**; v1's suspicion was unfounded. |
| Graph layout (later) | **`@dagrejs/dagre`** (scoped!) | MIT | v3.1.0, actively maintained. The *unscoped* `dagre`/`dagrejs` is the dead one. |
| — ELK | avoid | EPL-2.0 | **v1's reason was wrong.** EPL-2.0 is file-level; consuming an unmodified dep doesn't infect you. The real disqualifier is a ~1.5MB GWT bundle + worker requirement. |
| Icons | Lucide | ISC | Carries Feather's original MIT copyright — preserve it in NOTICE. |
| Fonts | Inter + JetBrains Mono | OFL-1.1 | Neither reserves a font name, so subsetting *and* keeping the names is clean. **But** OFL requires license text + copyright ship *with* the files; self-hosting is distribution. Needs a `licenses/` build step. |
| Tiles (deferred w/ Map) | OpenFreeMap | MIT code / **ODbL** data / **CC-BY** OpenMapTiles schema | v1 conflated three licenses into two. Mandatory string: `© OpenMapTiles © OpenStreetMap contributors`. Donation-funded, one maintainer, **no SLA** — name the weekly-planet-dump self-host fallback rather than discovering it during an outage. |

**Data sources:**

| Source | Verdict |
|---|---|
| World Bank Indicators | ✅ Ship. CC-BY 4.0, ~1,000 req/hr. **Attribution mandatory**, propagates to every rendered chart. |
| REST Countries | 🟡 Data is CC0/clean; the project is a single hosted SPOF and the self-hosted version is explicitly unmaintained. **Vendor a snapshot** rather than depend on it. |
| **Open-Meteo** | 🔴 **CUT from defaults.** Free tier is **non-commercial only**. v1 listed it under "all permissive" — shipping it as a default resolver hands every downstream commercial user a ToS breach they didn't opt into. Opt-in adapter behind an explicit gate, or not at all. |
| Wikipedia REST | 🔴 **Not client-side, ever.** Browsers cannot set `User-Agent`, which Wikimedia's policy *requires* — non-compliant by construction. Wikimedia is rolling out global limits through 2026 aimed at exactly this traffic. Content is CC BY-SA (**share-alike**). Server-only, if at all. |

**Therefore `@orrery/resolve` is a server package, stated as such.** v1 described it as
"fetch only" and implied isomorphic. From a browser you get CORS problems, rate limits
charged against the *end user's* IP (catastrophic behind corporate NAT), no `User-Agent`,
and zero cross-user caching. Ship a `/api/resolve` handler, a documented TTL per source, a
compliant UA, and a **bundled snapshot fallback** so the demo works offline and never
hammers a free API.

Every resolver descriptor carries `{license, attribution, commercialUse}`; CI fails on a
resolver with no attribution string and generates `THIRD_PARTY_DATA.md` from them. Blocks
rendering sourced data have a required attribution slot in the token system.

**Also, not a license issue:** Natural Earth encodes editorial choices on disputed
boundaries (Kashmir, Crimea, Taiwan, W. Sahara). A `Globe` ships those to every user.
Document it.

## 8. Safety — absent from v1 entirely

One page, written in step 0: `Prose` renders markdown → named sanitizer, no raw HTML.
Image URLs → allowlist or proxy (model-supplied URLs are a tracking-pixel and SSRF
surface). `source:` strings are **parsed against a registry of known resolvers, never
templated into a URL** → SSRF. No prop accepting arbitrary URL schemes.

v1 cited A2UI, whose entire pitch is "declarative data, never executable code," and adopted
the citation without the posture.

## 9. Degradation & versioning

Unknown block → `Prose` summarising props. Unknown prop → drop + dev warning. Failed ref →
skeleton, then an inline error chip. Partial stream → render what `BlockPartial` validates.
Never a blank screen; never a thrown error reaching the user.

**`version` field + `migrations/` from commit one.** Specs get persisted into chat
transcripts. When `Chart` drops a prop in v2, every stored conversation renders wrong.
Cheap now, impossible later.

## 10. Measurement — thresholds, not metrics

v1 listed metrics with no pass numbers, which makes a gate unenforceable, and used the same
30 examples as both few-shot and eval set (training on test).

- Split: ~30 few-shot, ~120 **held-out** eval prompts.
- Label each with an **acceptable set** of blocks, not one gold answer — "show me America"
  has ≥3 defensible answers and a single label punishes correct behaviour. Score set
  membership.
- Thresholds: schema-valid ≥99% · block choice in-set ≥85% · renders-without-error 100% ·
  p50 output ≤400 tok · `cache_read_input_tokens > 0`.
- **Recorded HTTP fixtures** in PR CI; one nightly job hits live APIs and opens an issue on
  drift. Never let PR CI depend on the World Bank.
- `/gallery` renders every block in every state **with no model in the loop.** (Kept from
  v1 unchanged — it's the best cheap idea in the document.)
- Pixel goldens: **exclude `Globe`** (WebGL is not reproducible across GPU/driver/fonts);
  assert its DOM/props contract instead. Defer goldens generally until block visuals settle.
- "Haiku 4.5 is sufficient" is a **hypothesis**, demoted to an eval output, not a finding.

Brazil, watches the panel update with no model call, then asks "why is it so far behind?"
and gets an accurate answer. If that screen recording exists, the project is proven.
