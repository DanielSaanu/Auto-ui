# Auto-UI — Plan v1

## 0. The thesis

Give a model a *closed vocabulary* of themed, interactive blocks plus the data to fill
them, and let it emit a ~200-token JSON spec instead of ~3000 tokens of React. Cheap,
consistent, safe, and the output looks like one product instead of thirty.

## 1. What has already been solved (do not rebuild)

Research as of Sept 2026:

- **Vercel `json-render`** (Apache-2.0, ~13k stars, Jan 2026): `defineCatalog()` with Zod
  props, `defineRegistry()` mapping to implementations, flat `{root, elements{}}` spec,
  `emit()` action flow, `setState` + `$state`/`$cond`/`$template` expressions,
  `createSpecStreamCompiler()` for progressive render. Renderers for React/Vue/Svelte/
  Solid/RN, plus PDF/email/video/3D targets. Ships 36 shadcn components.
- **Google `A2UI` v0.9** (Apache-2.0): framework-agnostic *wire standard* for declaring UI
  intent, client-defined functions, client→server data sync.
- **Thesys C1 + Crayon** (MIT): OpenAI-compatible endpoint that returns UI.

**Conclusion: the protocol layer is commoditised. Building a third element-tree format is
wasted work and the plan must not do it.**

## 2. What is *not* solved — the actual gap

Every existing catalog is **app chrome**: buttons, cards, forms, tabs. shadcn's 36
components cannot *show you America*. Nobody has shipped:

1. An **explanatory block vocabulary** — globe, choropleth, timeline, node-graph,
   comparison — designed specifically to be *parameterised correctly by a language model*.
2. A **token system** those blocks are coherent under, in light and dark, at chat density.
3. A **prompt pack generated from the schemas**, so the model's instructions cannot drift
   from the code.
4. **Bundled public-domain data + free API resolvers**, so `Globe` is one prop, not a
   three-day GIS integration.
5. **Data-by-reference**, so statistics never pass through the model at all.

Auto-UI is therefore: **a design system, block catalog, prompt pack and data layer for
explanatory generative UI. Protocol-agnostic. Ships a thin reference renderer you are
expected to throw away.**

## 3. Layering — the bones/renderer split

Strict one-way dependency graph. Packages *above the line* are the durable IP; packages
*below* are disposable.

```
  @auto-ui/tokens     zero deps          design tokens -> CSS vars + TS
  @auto-ui/schema     zod only           block schemas, envelope, validation, versioning
  @auto-ui/prompt     build-time only    catalog.md + tool.json generated FROM schema
  @auto-ui/data       fetch only         public-domain datasets + free-API resolvers
  ---------------------------------------- throwaway line ----------------------------
  @auto-ui/react      reference renderer
  apps/playground     chat demo
  @auto-ui/bridge-*   json-render / A2UI adapters
```

**Hard rule, CI-enforced:** nothing above the line may import React, any DOM API, or any
rendering library. Enforced by `dependency-cruiser` + a lint rule. This single constraint
is what makes the top half genuinely disposable.

**Envelope:** `@auto-ui/schema` defines a ~40-line envelope that is a deliberate *subset*
of json-render's `{root, elements{}}` shape, so `bridge-json-render` is near-zero code and
we inherit their streaming compiler and four extra framework renderers for free — without
depending on them.

## 4. The block catalog

Organised by **intent**, not by widget. 24 blocks total; slice 1 ships 10.

| Tier | Blocks |
|---|---|
| structure | `Surface` `Stack` `Grid` `Section` |
| summary | `Prose` `Metric` `Callout` `KeyValue` |
| quantitative | `Chart` `Table` `Distribution` `Progress` |
| spatial | `Globe` `Map` `Region` |
| relational/temporal | `Timeline` `Diagram` `Tree` `Compare` |
| input | `Choice` `Slider` `Form` |
| media | `Gallery` `Code` |

**One block, many kinds.** `Chart` takes `kind: line|bar|area|scatter|donut` rather than
five component names. Fewer names for the model to recall, discriminated union keeps it
typed, smaller prompt.

### Prop design rules (the real contribution)

1. **Data-shaped, never pixel-shaped.** No `width`, `color`, `margin`, `className`. Ever.
   The model says *what it is*; the theme says *how it looks*.
2. **Flat and named**: `{rows, x: "year", y: "gdp"}`, not nested config objects.
3. **Enums over free strings**: `emphasis: "primary"|"muted"`, never `color: string`.
4. **≤8 props per block, ≤3 required.** More than that means it should be two blocks.
5. **Everything optional renders.** A partial spec from a half-finished stream must draw.
6. **Data by reference, not by literal.**
   `{source: "worldbank:NY.GDP.MKTP.CD", region: ["US","CN"], year: 2024}`
   The model *names* a dataset; the runtime resolves it. Cheaper, and the model
   structurally cannot hallucinate the numbers.

## 5. Tokens

- Source of truth: `tokens.json`, DTCG-shaped. Primitives -> semantic aliases -> component.
- Ramps authored in **OKLCH** so light/dark are generated from one definition and stay
  perceptually even.
- Separate **categorical data palette**, contrast-validated in both themes.
- Axes: color, type scale, space, radius, motion, and **density** (`compact|normal|roomy`)
  — chat surfaces need compact.
- Emits: `theme.css` (custom properties), `tokens.ts` (typed consts), per-theme files.
- One shipped theme ("Slate") plus `theme-gen` — supply a brand hue, get a coherent system.

## 6. Prompt pack — generated, never hand-written

- `catalog.md` — compact block reference, generated from the Zod schemas. **Budget: <2500
  tokens** for all 24 blocks; CI fails the build if exceeded.
- `heuristics.md` — intent -> block selection rules. The *only* hand-written file.
- `examples.jsonl` — ~30 (prompt -> spec) pairs. Doubles as few-shot and as the eval set.
- `tool.json` — JSON Schema for tool-use with `strict: true` (constrained decoding).
- Build asserts: every block appears in >=1 example; token budget met.

## 8. Interaction — and why it must usually not call the model

Blocks emit `{block, action, value}`. Three tiers:

1. **Local** (default): renderer-held state. Spin the globe, sort the table, switch a tab.
   **Zero model calls.**
2. **Refetch**: a data reference re-resolves (change the year on a choropleth). Zero model
   calls.
3. **Escalate**: sent back to the model as a turn. Only when *meaning* changes.

A model round-trip per click is fatal to both cost and latency. Tier 1 is the default and
blocks must declare escalation explicitly.

## 9. Cost argument

- Catalog prefix is static -> **prompt caching** makes it ~free after the first call.
- Response is 150-400 tokens of JSON vs 2000-4000 of React: roughly an order of magnitude.
- Data references keep statistics out of the token stream entirely.
- Local interactions mean most user input costs nothing.
- The constrained catalog means **Haiku 4.5 is sufficient** for block selection; reserve
  Opus for the reasoning turn.

## 10. Correctness harness

- `pnpm eval` runs `examples.jsonl` against a live model and scores: schema-valid %,
  block-choice agreement %, renders-without-error %, output token count. This is what stops
  the catalog silently rotting as it grows.
- Playwright golden images for every block x {light,dark} x {compact,roomy}.
- `/gallery` route renders every block in every state **with no model in the loop** — you
  develop blocks without burning tokens.

## 11. Degradation

Unknown block -> render as `Prose` summarising props. Unknown prop -> drop + dev warning.
Failed data ref -> skeleton then inline error chip. Partial stream -> render what validates.
**Never a blank screen, never a thrown error reaching the user.**

## 12. Implementation steps

0. Workspace skeleton: pnpm, TS, CI, license policy, dependency-cruiser boundary check.
1. `tokens` + theme generation + static gallery shell.
2. `schema`: envelope + 10 block schemas + validator + degradation rules.
3. `prompt` generator + eval harness. **Before the renderer**, so quality is measurable.
4. `react` core: resolver, error boundaries, streaming, action bus.
5. Blocks in three waves: summary/quant -> spatial -> relational.
6. `data`: resolvers, cache, free-API adapters.
7. `apps/playground`: chat shell, Claude tool-use `strict:true`, progressive render.
8. Bridges (json-render, A2UI), docs, "fork me" guide.
