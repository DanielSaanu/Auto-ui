# Orrery — Plan v3
*(working name; "Auto-UI" collides with "A2UI" aloud. User's call.)*

## 0. What this actually is

**A themed, LLM-fillable block pack for explanatory UI, plus the specification that makes
it portable.** It is an integration layer. That is not a euphemism and not a fallback —
it is the most valuable thing here, because it is the only thing that delivers the brief's
actual sentence: *easy and cheap and consistent and themed.*

v2 let "where's the moat?" set its scope, and in doing so demoted **themed** — the word the
brief uses — to a footnote while promoting a defensibility argument nobody asked for. That
was backwards. The theming and integration layer is the product. The globe is the demo that
sells it. Defensibility is a story told later, if anyone asks.

**Why a closed vocabulary, honestly.** Not because models can't write React — they can, and
that gap closes every generation. Four reasons that *don't* weaken as models improve:

1. **Persistence.** A 250-token spec can sit in a transcript and re-render in two years.
   Stored generated React is a rot-and-security liability the day you persist it. If blocks
   live in chat history, a closed vocabulary isn't a constraint — it's the only serializable
   option. *(This is the strongest argument and neither v1 nor v2 made it.)*
2. **Determinism.** The same question twice yields the same interface.
3. **Theming by construction.** Generated React uses your tokens *most* of the time. A
   catalog uses them 100% of the time.
4. **Interaction at zero marginal cost.** Dragging is 0 tokens and 0 network because the
   behaviour is compiled in, not generated.

**And the ceiling is real.** "Show me the electoral college as a cartogram with a scrub bar"
has no block. v2 degraded that to `Prose` — *silent* mediocrity, the worst failure mode,
because the user never learns the system couldn't. So the vocabulary gets an explicit
**escape hatch**: one enum value in the action vocabulary that hands off to code execution
and says so out loud. Closed catalog + escape hatch beats both pure positions. It costs
one enum value now and is very hard to retrofit.

## 1. The acceptance trace — corrected

v2's trace was the document's foundation and it **could not be executed.** Three independent
reviewers confirmed it, one by running the APIs. It hallucinated two statistics in its first
rendered line (and got the population wrong by 2M — the real 2024 figure is 340,003,797),
its choropleth prop rendered a flat monochrome ball, its `focus` prop had no data to resolve
against, and its digest call silently truncated to the wrong 50 of 70 rows.

**Rule that produced the bug:** narration streams before any tool returns, so narration can
only come from parametric memory. **Fix: phase-1 narration carries no figures. Numbers exist
only in blocks and in digest output.**

```
USER: show me america

(phase 1, text, ~400ms — QUALITATIVE ONLY, no figures)
  "Here's the United States — pulling population and GDP now.
   Drag to spin it, tap any country to compare."

(phase 2, tool call, ~250 tokens)
{ "v": 1, "blocks": [
  { "id": "b1", "type": "Choropleth", "projection": "sphere",
    "focus": {"iso3": "USA"}, "highlight": ["USA"],
    "fill": { "source": "worldbank:SP.POP.TOTL", "year": "mrv",
              "entities": "sovereign", "scale": "log",
              "noDataColor": "muted", "legend": true } },
  { "id": "b2", "type": "Metric", "group": [
    { "label": "Population",
      "ref": {"source":"worldbank:SP.POP.TOTL", "entity":{"$from":"b1.selection"}, "year":"mrv"} },
    { "label": "GDP",
      "ref": {"source":"worldbank:NY.GDP.MKTP.CD","entity":{"$from":"b1.selection"},"year":"mrv"} } ] } ] }

(frame) narration, then the map with the US lit, two tiles beneath.
(drag)     rotates. 0 model calls, 0 network.          <- the best line in the plan
(tap BRA)  b2 re-resolves via the $from binding. 0 model calls.
           transcript gains ONE REPLACED snapshot line:
           [ui state] b1: focus=BRA, highlight=[BRA]; b2: entity=BRA

USER: why is it so far behind?
  -> digest(NY.GDP.MKTP.KD + NY.GDP.PCAP.CD, [BRA,USA], 1990..mrv)
     -> {..., priceBasis:"constant-2015", caveats:[...], series12:[...]}
     -> accurate narration. Two model round trips, ~3-5s. Stated honestly.
```

Four corrections visible in that spec, each forced by a measured finding:
- `entities:"sovereign"` — without it, World Bank `/country/all` returns aggregates (World
  = 8.14B, IDA & IBRD total, Low & middle income) as the top ten and every real country
  lands in the bottom 17% of the ramp. **Flat ball.**
- `scale:"log"` — population spans nine orders of magnitude; linear renders everything but
  China and India identical.
- `year:"mrv"` not `2024` — specs get persisted; a hardcoded year is wrong in January 2027.
- `{"$from":"b1.selection"}` — a **closed, non-string** binding. v2 had *no mechanism at
  all* for "tap Brazil → panel updates," and the obvious repair (templating
  `@$globe.selection` into the source string) would violate our own SSRF rule.

**Honest latency:** ~400ms to first narration token; **3.5–4.5s to an interactive map on
mid-tier mobile, cold.** v2's "2.4s" was a desktop-warm number quoted against a mobile-cold
threshold. And for the sphere, see §4 — it can't be in the server-streamed paint at all.

| **Google A2UI** v0.9.1 | Apache-2.0 | Wire standard **+ a client-held catalog concept**. 15 chrome components, zero viz. |
| **AntV `GPT-Vis`** | MIT | 26 LLM-targeted chart types — the whole quantitative **and** relational tier. LLM DSL, MCP server, 3 themes, **streaming + fault-tolerant partial data.** |
| **MCP Apps** (SEP-1865) | — | Host↔server UI incl. **standardized CSS custom properties for host theming.** |

Also: "model emits declarative chart JSON, runtime renders" is a **solved, published
pattern** (Vega-Lite, NL4DV, ChartGPT). And **data-by-reference is already published** in the
MCP literature (arXiv 2510.05968, ResourceLink for large datasets; MCP discussion #930).
v2 called it "unoccupied." It isn't — at the pattern level it's written up today.

**So: no element tree, no prompt generator as a headline, no charts or diagrams from
scratch, and no novelty claim on declarative specs.** What is left is taste, theming,
compliance and one genuinely empty tier (spatial). That is enough to build. It is not a moat
and the plan no longer pretends otherwise.

## 3. Shape — three phases, and the first one is five days

v2 was ~18.5 developer-weeks with its riskiest unknowns scheduled thirteen weeks in. That
is backwards, and it's an org's process applied to a one-person prototype.

**Phase A — prove it. 5 days, one app, no monorepo, ~1000 lines.**
No packages, no workspace, no conformance suite, no migrations, no eval harness.

| Day | Work | Kill criterion |
|---|---|---|
| 1 | **`Choropleth` 2D first** (d3-geo + topojson + world-atlas 110m). Hand-write the spec, no model. | Does the join work and does it look good? |
| 2 | **The model.** 4 zod schemas → `strict:true` tool. One Sonnet call. Type "show me america." Hand-run 20 prompts, eyeball the specs. | Does the model fill the props correctly first-try? |
| 3 | **`/api/resolve`**, ~150 lines + `digest`. **Feel the narration question here**, both ways, and decide with your eyes. | Is digest-grounded narration worth the extra round trip? |
| 4 | **Close the loop.** Stable IDs, `$from` binding, tap→local state→state snapshot→next question answered correctly about Brazil. | **This is the day that matters.** |
| 5 | **Theme + record.** One OKLCH `tokens.css`, light+dark. Then a *second* theme that makes the identical spec look like a different product. Record 30 seconds. | Does the theming claim hold? |

Day 1 builds the **2D** map, not the globe, on a measured argument: `d3-geo` is **709 bytes
gzipped**; globe.gl is **525 KB gz / 1.89 MB parsed**. The 2D version proves the join table,
the resolver, the colour scale and the legend for ~45 KB instead of ~565 KB — and it is the
fallback you need anyway when WebGL is unavailable or the context budget is spent. The globe
is `projection: "sphere"` on the same block, added in phase B.

**Phase B — extract the bones (~4 weeks).** Only after phase A has moved. Pull the four
files into `contract` / `tokens` / `geo` / `resolve`, add the sphere projection, wire
`catalog-json-render`, add `Chart` as a GPT-Vis adapter.

**Phase C — harden (~4 weeks, optional).** Conformance suite + static-SVG second renderer,
eval harness with thresholds, `migrations/`, goldens.

**The bones are four files**, and this is the answer to "throw away the top half":
`blocks.ts` (prop schemas) · `actions.ts` (action vocab + state-snapshot format + the `code`
escape hatch) · `tokens.css` · `resolve.ts`. Those survive a rewrite. A monorepo is what you
build once those four have earned it.

**Disposability is proven by a second renderer passing a conformance suite** — not by a lint
rule, and not by v2's Ink renderer, which would have implemented `Prose`/`Metric`/`Table`
and tested string formatting while exempting every surface that can actually leak. The
honest test is a **static SVG renderer** covering `Choropleth` + `Metric` + `Prose`: no
React, no DOM, no interaction, and it forces "what to draw" apart from "how to draw it" on a
block that is part of the moat. It's also independently useful (email, PDF, OG images).
Phase C.

## 4. The spatial tier — the parts that are actually hard

Everything here was measured, not recalled.

**`world-atlas` carries no country codes.** Its `properties` is exactly `{name}`. So
`highlight: ["USA"]` has nothing to join on. This is the single biggest unbudgeted item in
v2 and it needs a vendored **`geo`** package: numeric ↔ alpha-3 ↔ World Bank, ~15
hand-adjudicated exceptions, a `noData` sentinel, and a CI test asserting **every one of the
177 polygons either joins or is on a named exclusion list**. ~2.5 days.

Named failures it must handle:
- **Natural Earth `ISO_A3 == "-99"` for France and Norway** (also N. Cyprus, Kosovo,
  Somaliland). A naive `ISO_A3` join renders **two holes in Europe** — and the file that has
  this is the one shipped in three-globe's own example, i.e. where the spike will start.
  Prefer `ISO_A3_EH` → `ADM0_A3` → manual override.
- **Kosovo has WB data (`XKX`) and world-atlas geometry with no `id`.** Manual rule.
- **Somaliland / N. Cyprus** have geometry and no data anywhere — must render as explicit
  "no data," not as a join miss, or the legend lies.
- **Five WB rows have a blank `countryiso3code`** (the income groups) — keying by it
  collides all five on `""`, last one wins, silently.
- **177 polygons vs 217 WB countries.** ~40 (Aruba, Macao, small island states) have no
  polygon at 110m and vanish silently.
- Stay on **110m** (39 KB gz). 50m is 236 KB gz *and makes the join worse*: five features
  with no id, plus **a duplicate id `036` shared by Australia and Ashmore & Cartier**, so
  `new Map(...)` silently drops Australia.

**`focus` needs a vendored camera table, not computed centroids.** `geoCentroid(France)` is
**open ocean off Portugal** (French Guiana drags it) — same for NLD, NOR, NZL, GBR.
`geoBounds` on Russia and Fiji returns `maxLon < minLon` (antimeridian), so any
`altitude = f(bboxWidth)` goes negative or ~350°. USA's bounds span 105° because of the
Aleutians, so bbox-derived altitude zooms past "the US lit." **This is the same vendored
table v2 cut `Map` to avoid building — the cut saved nothing here.**

**The sphere cannot be server-rendered.** `globe.gl` reads `window.THREE` at **module
scope**; `import Globe from 'globe.gl'` throws in Node. It must be `dynamic(..., {ssr:false})`
behind a fixed-height skeleton, or the narration the user is reading jumps on hydration.
Add a CI test that imports the block barrel in Node and asserts it doesn't throw.

**Bundle gate, day 1 of phase B:** build through the real bundler and assert the globe chunk
is **< 600 KB gz**, specifically checking whether `three/webgpu` (2.28 MB, imported
statically by `three-render-objects`) and `h3-js` (213 KB, for a hexbin layer we never use)
got shaken out. Add `resolve.dedupe: ['three']` — globe.gl pins three as a hard dep,
three-globe declares it a peer, and json-render ships an R3F renderer, so three copies in
one app is live and fails as silent `instanceof` errors.

**Mobile rules, in the block spec, not discovered later:** wheel **never** zooms
(`controls().enableZoom = false` — there's no top-level API, you reach into three.js);
globe ≤55vh so there's always scroll gutter; tap-to-activate overlay below 600px, because
OrbitControls' default `touches.ONE = ROTATE` means a one-finger swipe rotates the globe
instead of scrolling the transcript and **traps the user mid-conversation**;
`setPixelRatio(min(1.5, dpr))`; `pauseAnimation()` on IntersectionObserver exit; **one live
WebGL context per transcript** with static-snapshot fallback for the rest, because browsers
cap concurrent contexts around 8–16 and a chat surface will emit a second globe.

**Sub-national is out of scope.** `world-atlas` objects are exactly `['countries','land']`.
`"US-TX"` cannot render; `"Bay Area"` needs the geocoder we cut. Say so.

## 5. Data — `digest` v2, and why v1's version was a laundering mechanism

v2's digest returned `{min,max,first,last,delta,cagr,units,n,outliers}`. Measured against
the live API, that shape **converts model uncertainty into a structured, authoritative-looking
object**:

- **It truncates silently.** WB's default `per_page` is **50**; v2's own flagship digest call
  needed 70 rows. USA's `first` becomes 2010 instead of 1990, `delta` spans 14 years instead
  of 34. Well-formed object, wrong numbers, HTTP 200 throughout.
- **`units` cannot be populated.** WB's `unit` field is an **empty string** in both the
  observation and the indicator metadata. It must be scraped from the indicator name or
  hand-vendored.
- **Nominal vs real is unrepresentable.** Brazil's GDP CAGR is **5.24%** in current US$ and
  **2.36%** in constant 2015 US$. The series also shows a 44% "collapse" from 2011 to 2020
  that is almost entirely BRL depreciation. `outliers` makes this *worse* — 2011 and 2020
  are FX artifacts, and flagging them invites the model to narrate them as economic events.
- **`n` hides gaps.** Syria 1990–2024 has 2 nulls. Two series with `n:33` can be consecutive
  or war-shaped. The model draws a trend line through the hole.
- **It has no causal content**, so it does not answer the trace's own payoff question. And
  the right first-order answer is *per capita* (BRA ~$10.3k vs USA ~$86k) — a second series
  and a division the digest structurally cannot do.

**Digest v2:** `{first:{year,value}, last:{year,value}, min, max, n, nMissing, gaps[],
cagr, priceBasis:"current"|"constant-2015"|"ppp", currency, comparableAcrossTime,
units, unitsSource, series12[], caveats[]}` — `series12` being a ≤12-point resample, which
closes the entire "when did X happen / who overtook whom" class for tens of tokens. A
`current US$` series emits a **mandatory caveat string** the system prompt requires the model
to honour. Ship `NY.GDP.MKTP.KD` (constant) and `NY.GDP.PCAP.CD` (per capita) as first-class.

**Resolver realities** (v2 gave this one table row; it is ~20 developer-days):
pagination · aggregate filtering (`region.id === 'NA'` marks all 78, and it needs a *second*
metadata call) · the join table · the vendored camera table · cache keying with a resolver
version in the key · **single-flight dedup and an abort race** — aborting the HTTP request is
the easy 20%; the hard part is a monotonic request token per block id so a stale resolve
can't overwrite a newer one, or the panel shows Brazil's data under Argentina's title.

**Two corrections to v2's own reasoning:**
- v2 led with CORS as the reason the resolver must be server-side. **World Bank sends
  `access-control-allow-origin: *`.** The conclusion is still right — per-end-user IP rate
  limits, no settable `User-Agent` for Wikimedia, no cross-user cache — but not for that reason.
- v2 said a bad indicator "returns 200 + empty array." It actually returns **HTTP 200 with
  an error envelope** (`{"message":[{"id":"120","key":"Invalid value"}]}`). The genuinely
  silent case is a *valid* code with no data → `value: null`. The error taxonomy gets
  rewritten around measured behaviour: `unknown-source` / `unknown-indicator` /
  `unknown-entity` / `no-data` / `partial-data` / `upstream-5xx` / `rate-limited` /
  `timeout` / `aborted`, each with its own UI affordance.
- "~1,000 req/hr" is folklore — not published, no rate-limit headers. Back off on 429/503
  rather than budgeting client-side.

**Licensing** (carried from v2, all verified): **Open-Meteo is non-commercial only — cut
from defaults.** **Wikipedia is client-impossible** (browsers can't set `User-Agent`, which
Wikimedia's policy requires) and is CC BY-SA share-alike. World Bank is CC-BY with
**mandatory attribution that propagates to every rendered chart**. REST Countries is a
single unmaintained SPOF — vendor a snapshot. Every resolver descriptor carries
`{license, attribution, commercialUse}`; CI fails a resolver with no attribution string and
generates `THIRD_PARTY_DATA.md`. Fonts need an OFL `licenses/` build step. Natural Earth
encodes disputed boundaries (Kashmir, Crimea, Taiwan, W. Sahara) — that ships in the hero
block to every downstream user and needs a stated policy, not a sentence.

## 6. Contract details that v2 got wrong

**`strict:true` requires *every* property in `required`** (optionality is a `["T","null"]`
union), and Anthropic rejects root-level `anyOf`/`oneOf`. So v2's rule "≤8 props, ≤3
required" was *still* incompatible with `BlockStrict` after v2 claimed to have fixed it.
Restated: **"≤3 required" is a semantic rule about what the model must think about, not a
schema rule.** The model emits all props with nulls — which also inflates the output-token
estimate. Day-1 spike aims at *this* hypothesis, plus the `Chart.kind` discriminated union.

**State echo is a snapshot, not a log, and it lives in the contract.** v2 appended
`[ui] globe: selected BRA` per interaction. After 40 interactions the model sees a *history*
of selections and must infer that the last one wins; if the lines fall out of a truncated
window, the state vanishes silently while the blocks stay mounted. And the strings were
produced by the renderer — *below* the line — while model behaviour depended on their exact
format, so the contract had silently leaked into the disposable half. Fix: **one replaced
snapshot per turn**, regenerated from live renderer state, with the vocabulary defined in
`actions.ts`. Same token cost, unambiguous, cannot go stale.

**`Chart` is a GPT-Vis adapter. Decided, on paper.** v2 conceded the quantitative tier in §1
and then kept "GPT-Vis *vs* Recharts" open in step 0 while still shipping its own `Chart` —
which would have quietly un-conceded it. They aren't interchangeable behind an adapter
anyway: GPT-Vis takes a spec in its own DSL and owns rendering, theming, streaming and
tooltips; Recharts takes React children and owns nothing.

**The theming claim is downgraded to what's achievable.** "A G2 chart and a three.js globe
look like one product" is not deliverable from one token file. Canvas has no CSS cascade, so
custom properties never reach `fillStyle`; G2 re-derives colour ramps through d3-color in
sRGB, voiding OKLCH perceptual evenness exactly at the choropleth legend; and three.js
converts sRGB→linear→out while globe.gl's globe is *lit*, so the drift varies with the
lighting term and can't be calibrated away. What breaks first, visibly: **the dark-mode
toggle** — CSS flips instantly while the chart and globe lag, each via a different API. Real
claim: *one token source generates our CSS variables, a matching G2 theme object, and a
categorical palette contrast-validated in both themes* (~1 week), plus a budgeted runtime
theme-push on `matchMedia`. Drop "one product" or fund the stylesheet fork.

**Other fixes:** `json-render` v0.21.0 is **pre-1.0** and is simultaneously the distribution
channel and the streaming engine — pin it, and write an exit note. Two-phase narration is
**not portable**: Anthropic emits `text` then `tool_use` natively, but OpenAI's
`tool_choice:"required"` typically suppresses content and Gemini often returns no text — so
the tool payload carries a `narration` fallback field. Require the payload to declare which
refs its narration asserts, and validate each exists. Add a **catalog token floor** assert
(≥1,024 to cache on Sonnet) alongside the ceiling — v2 deleted the budget rule and left the
inverted constraint unwritten. And give `catalog.md`/`heuristics.md`/`examples.jsonl` an
owning step; v2 deleted the step along with the retracted novelty claim and lost the artifact.

interactive map with the US lit, drags it, taps Brazil, watches the tiles update with no
model call, then asks "why is it so far behind?" and gets an accurate, specific answer that
cites constant-dollar and per-capita figures it was handed rather than recalled. Then you
flip one CSS file and the identical spec re-renders as a visibly different product.
