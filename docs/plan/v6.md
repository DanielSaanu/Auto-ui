# Orrery — the plan, v6

*Working name. "Auto-UI" and Google's "A2UI" are indistinguishable spoken aloud.*

Facts marked **[measured]** were checked against a live API or package registry on the date
given. Facts marked **[asserted]** were not, and are called out wherever they are
load-bearing.

---

## 1. The idea

A **space**: a durable surface that accumulates. You write into it; things appear and stay.
Some stay for a minute, some until you delete them, and "stay" means *as long as the server
holding the data does*. An agent builds in this space — placing, updating and removing
elements — and elements in the space can call an agent back.

The agent does not write UI code. It emits **specs** (a few hundred tokens of JSON selecting
and parameterising blocks from a registry) and **queries** (a closed grammar describing what
data goes in them). The runtime turns those into themed, interactive, persistent artifacts.

### 1.1 The user of this system is a model

This is the design target, stated plainly because everything downstream follows from it: the
author writing into a space is **a sufficiently sophisticated model**, not a human. Human
ergonomics and model ergonomics diverge, and where they do, this system optimises for the
model:

- **A closed vocabulary beats a flexible one**, because the failure mode being designed
  against is plausible-but-wrong generation, not limited expressiveness.
- **Encoding is derived, not specified.** The agent emits a query and at most a one-word
  mark hint; scale, axes, legend and colour channel are the renderer's job. Every parameter
  removed from the agent's surface is a parameter it cannot get subtly wrong.
- **Validation errors carry repair instructions**, because the consumer of an error message
  is something that will retry, not something that will read documentation.
- **≤8 props, ≤3 required** (§4.9) is a token-budget and attention rule, not a taste rule.
- **The system prompt is generated from the schemas**, so the schemas *are* the docs, and
  they cannot drift from what the validator enforces.

A human can drive this too, through the renderer's own controls. But the contract is shaped
for the model, and the places where that costs human convenience are deliberate.

### 1.2 Why not let the model write React?

Three reasons that do not weaken as models improve, and one that does:

1. **Persistence.** The space's value is that it survives. A JSON spec re-renders in two
   years; stored generated React is a rot-and-security liability the day you persist it.
2. **Theming by construction.** Generated code uses your tokens *most* of the time. A
   registry uses them 100% of the time.
3. **Free interaction.** Spinning a globe, sorting a table, scrubbing a year costs 0 tokens
   and 0 network, because the behaviour is compiled in. In a space you return to,
   interaction vastly outnumbers generation.
4. *(Weakens over time)* **Reliability.** Selection from a registry fails less than codegen.
   That gap narrows every model generation. Do not build the case on it.

### 1.3 Determinism, stated correctly

Two different claims, kept apart:

- **Render determinism** *(guaranteed, tested)*: the same spec produces the same render. A
  renderer property, verified by the conformance suite.
- **Selection stability** *(measured, never guaranteed)*: the same request produces a similar
  spec. Has a threshold and an eval harness, and will never be 100%.

Only the first is load-bearing for persistence — which is why persistence survives the second
being imperfect.

**The ceiling is real and gets an explicit exit.** Some requests have no block. Degrading
silently to a paragraph is the worst outcome, because the user never learns the system could
not. Refusal is a **first-class element type** (§4.7), not an absence.

## 2. The substrate, and its extension API

The product is a substrate with an extensible registry. That claim is only worth making if
the extension API is specified, so here it is — signatures first, prose after.

### 2.1 What is core and what is a pack

| Layer | Core? | Contents |
|---|---|---|
| Space protocol | Core | Elements, ids, lifetime, versions, snapshot, invoke |
| Query grammar | Core | `source × select × entities × range × filter × order × limit` |
| Asset addressing | Core | `{pack, name}` through a registry |
| Tokens + emitters | Core | `tokens.json` → CSS, TS, G2 theme, sprite palettes |
| Blocks | **Pack** | `core@1` ships 8; others register |
| Resolvers | **Pack** | `worldbank` is a bundled *example*, not core |
| The geo table | **Pack** | A World Bank/Natural Earth join artifact, in `geo@1` |

### 2.2 `defineBlock`

```ts
type BlockDef<P extends z.ZodType> = {
  name: string                    // "Choropleth" — unique within the pack
  props: P                        // the zod schema; SOURCE OF TRUTH for prompt + validator
  tiers: Tier[]                   // which of local | refetch | invoke it supports
  fields: BoundField[]            // what OTHER elements may bind to (§4.6)
  mobile: { minH: "s"|"m"|"l"; gestures: Gesture[] }
  a11y: { role: string; keyboard: string }    // required, not optional — §7.4
  render: (props: z.infer<P>, ctx: RenderCtx) => unknown   // renderer-specific
}

declare function defineBlock<P extends z.ZodType>(def: BlockDef<P>): BlockDef<P>

type PackDef = {
  id: string                      // "core", "geo", "acme-crm"
  version: number                 // MAJOR only; see §2.4
  blocks?: Record<string, BlockDef<any>>
  resolvers?: Record<string, ResolverDef>
  assets?: AssetPackDef
}
declare function definePack(def: PackDef): PackDef
```

`props` being the source of truth is the load-bearing part: the system prompt, the validator
and the docs are all generated from it, so they cannot disagree.

### 2.3 `defineResolver` — and why a resolver is data, not code

```ts
type ResolverDef = {
  id: string                      // "worldbank" — the key a Query's `source` names
  measures: MeasureDef[]          // what `select` may contain, with units and price basis
  entities: EntityDef             // how `entities` resolves; named groups live here
  request: {                      // A DECLARATIVE REQUEST TEMPLATE, NOT A FUNCTION
    base: string                  // "https://api.worldbank.org/v2"
    path: PathSegment[]           // literals and NAMED PARAMETER SLOTS only
    query: Record<string, ParamSlot | string>
    paginate: { style: "page"|"cursor"; pageParam: string; sizeParam: string; max: number }
  }
  response: { rows: JsonPath; value: JsonPath; year?: JsonPath; entity?: JsonPath }
  licence: { spdx: string; attribution: string; commercialUse: boolean }
  cache: { ttlSeconds: number; keyFields: string[] }
}
```

**The security model, which is the reason for that shape.** A third-party resolver is a
**declarative descriptor interpreted by our client**, not code we execute. It cannot run
arbitrary logic on our server, because there is nowhere in the type to put any. Concretely:

- `path` and `query` accept **literals and named slots only** — never a model- or
  author-supplied string templated into a URL. Slots are filled from validated `Query`
  fields, and the host is fixed by `base`.
- `base` is checked against an **egress allowlist** at pack-install time, and resolved
  addresses are re-checked at request time so a rebound DNS name cannot reach internal
  network space.
- `response` paths are JSONPath evaluated against parsed JSON — no `eval`, no code.
- A resolver with no `licence.attribution` fails CI (§6.4).

**A code-backed resolver tier is deliberately absent from this plan.** It is the obvious next
ask, and it is a sandbox project with its own threat model. Descriptors cover every data
source considered here; when one genuinely cannot be described declaratively, that is the
moment to design the sandbox, not before.

### 2.4 Pack versioning, and what happens to old specs

Every spec carries `requires: ["core@1", "geo@1"]`. The rules:

- **Within a major, block props are additive-only.** New optional props, new enum members at
  the end. A `core@1` spec therefore renders on a `core@1.x` runtime unchanged.
- **A major bump means the old renderer stays.** `core@2` ships *alongside* `core@1`, not
  instead of it. Old renderers are small — they are pure functions over frozen data — and
  keeping them is cheaper than a migration that can silently change what a saved artifact
  says.
- **Retention is a stated policy, not an accident:** majors are supported for **5 years** from
  supersession. After that a spec renders as a stub. This is written into the product, shown
  in the UI on any element whose pack is within a year of expiry, and is the honest answer to
  "how long is forever".
- **A missing pack renders a labelled stub** — the element's title, its block type, its
  frozen data as a table if it has any, and the pack it needs. A stub is a failure; the point
  is that it is a legible one that still shows the data.

## 3. How it works

```
 you type ──▶ /api/turn ──▶ agent
                              │
                phase 1: prose streams to the space's log — NO figures (§3.1)
                              │
                phase 2: tool calls
                              ├── query(...)   ──▶ resolver ──▶ digest ──▶ back to the agent
                              └── place(...)   ──▶ zod validate ──▶ server assigns id
                                                        │
                                             element enters THE SPACE
                                                        │
 you drag / sort / scrub ──────────────────────────────▶ renderer-local state
                              │                            0 model calls
                              │                   refs re-resolve via /api/resolve
                              │
 element's own control ──────▶ invoke() ──▶ agent ──▶ place / update (§4.6)
                              │
 next turn ──▶ agent reads the space snapshot ──▶ grounded narration
```

**Phase-1 prose streams into the space's log, not into an element.** The log is the input
channel's own history — it scrolls, it is `ephemeral` by default, and nothing persists from it
unless the agent promotes it. This keeps two-phase streaming, which is worth keeping for
perceived latency, without smuggling a transcript back in as the container.

Four interaction tiers; blocks declare which they support:

| Tier | Cost | Examples |
|---|---|---|
| **local** | 0 tokens, 0 network | spin, sort, hover, paginate, scrub within the envelope |
| **refetch** | network only | a year outside the envelope, a different entity |
| **invoke** | model call, budgeted | an element's own control asks the agent something |
| **turn** | model call | you type |

### 3.1 No figures outside resolved data

Any number the agent produces before a tool returns is parametric recall. The rule therefore
covers narration *and* persisted prose — the latter matters more, because it is saved,
screenshotted and trusted.

**It is enforced in the validator, not by convention.** `Prose.text` rejects bare numerals;
figures enter only through `figures[]` bindings to resolved refs, and the rejection message
tells the agent how to repair it (§4.7, `Prose`).

*(Concretely: the real 2024 US population is 340,003,797 **[measured, World Bank
SP.POP.TOTL]**. A recalled "342M" above a tile showing the true value is worse than either
alone, because the tile lends it credibility.)*

## 4. The contract

### 4.1 Space and element

```ts
type SpaceId   = string  // "sp_" + ULID
type ElementId = string  // "el_" + ULID — SERVER-ASSIGNED, never model-invented

type Space = {
  id: SpaceId
  v: 1
  title: string
  elements: Element[]         // ordered; order is layout order
  createdAt: string
  requires: string[]          // ["core@1", "geo@1"]
  budget: SpaceBudget         // §4.6
}

type Element = {
  id: ElementId
  block: string               // "core/Choropleth"
  props: unknown              // validated against that block's zod schema
  lifetime: Lifetime
  layout?: { span?: 1|2|3|4; minH?: "s"|"m"|"l" }
  origin: { turn: number; at: string; by: "agent"|"user"|"invoke" }
  version: number
  invokeChainDepth: number    // §4.6 — inherited+incremented, server-written
  frozen?: FrozenData         // present iff lifetime.mode === "persistent"
}

type Lifetime =
  | { mode: "ephemeral" }
  | { mode: "session" }
  | { mode: "persistent"; pinned?: boolean }
```

**On the count.** The brief says "persistent or temporary, interchangeably" — two states.
This ships three, and the extra one is `session`. The reason: without it, every transient
thing an agent places (a progress note, a draft, a status line) is either written to the store
and needs cleaning up, or dies at the end of the turn and cannot survive the follow-up
question that refers to it. `session` is temporary-that-outlives-a-turn. If that distinction
proves unused in Phase A, collapse it — `ephemeral` and `session` differ only in when they are
swept, so merging them is a one-line change and no schema migration.

**Promotion is explicit and cheap** — `promote(el, "persistent")`, available to the agent and
to the user as a pin. Demotion is `release(el)`.

**Expiry is never silent.** An expiring element collapses to a stub carrying its title, its
type and a "rebuild" affordance that replays the originating query. Things quietly vanishing
from a space you trusted is the fastest way to stop trusting it.

**Ids are server-assigned and space-scoped.** The agent emits `place()` with local placeholder
names (`"$globe"`); the server assigns the ULID and returns the mapping. Elements are
addressed only by ids read from the snapshot. Two elements in one space can never collide, and
an agent cannot invent an id that resolves to someone else's element.

### 4.2 Persistence: the freeze, the envelope, and the bill

A persisted element must render from data it owns. Pointing at a live third-party API is a
bookmark, not persistence, and it is how a saved artifact silently changes what it says.

```ts
type FrozenData = {
  at: string
  envelope: "envelope" | "slice"
  resolvedYear?: number       // a concrete year, NEVER "mry"
  rows: unknown               // the resolved values
  receipts: Receipt[]         // source, units, licence, attribution, per ref
  digestVersion: string
  bytes: number               // counted, because §4.3 bills it
}
```

**The envelope is what makes interaction and offline-rendering compatible.** A frozen
`Choropleth` still offers tap-select and year-scrub, which need data beyond what is on screen.
So freezing captures a declared region of the query space, not a screenshot:

- **`envelope`** (default): the *whole* queried `entities × range` space is cached at freeze
  time. Every `local` interaction keeps working offline, forever, within it. Stepping outside
  — a year the query never asked for — is a `refetch`, and offline it is **disabled with a
  visible reason**, not silently dead.
- **`slice`**: only the displayed values are cached. Smaller; interaction offline is disabled.
  For elements where the envelope would be large and the interaction incidental.

Bindings follow the same rule: a frozen element's binding **re-evaluates against its own
frozen envelope**. A frozen `Metric` bound to a live `Choropleth.selection` tracks the
selection as long as the selected entity is inside the Metric's envelope, and shows an
explicit out-of-envelope state otherwise. The alternative — a frozen element quietly issuing
live network calls — would reintroduce exactly the drift freezing exists to stop.

**Refresh is explicit and bounded.** `refresh` re-resolves and creates version *n+1*. Version
history is what gives the space undo. It is also unbounded storage if left alone, so:

- **Keep the last 10 versions, plus any version the user pinned, plus the first.** Older
  intermediate versions are compacted away — spec kept, `rows` dropped, replaced by a receipt.
- **Per-space storage quota** covering `FrozenData` *and* uploaded datasets together, shown in
  the UI, enforced on write.
- Priced in §8.5, alongside tokens.

`mry` survives only as an authoring convenience: it resolves to a concrete year at use, and
the concrete year is stored. It needs a quorum — the most recent year with ≥ *q*% of requested
entities present, default 80 — and the resolver returns `{resolvedYear, coverage, excluded[]}`
which the renderer must surface. Without a quorum, "most recent common year" across 217 sparse
entities is either a decade stale or empty.

### 4.3 The query grammar

```ts
type Query = {
  source: SourceRef
  select: string[]                     // measure ids, e.g. ["NY.GDP.MKTP.KD"]
  entities?: EntitySel
  range?:  { from: number; to: number } | { recent: number } | { at: number | "mry" }
  filter?: Filter[]
  order?:  { by: string; dir: "asc" | "desc" }
  limit?:  number
}

type SourceRef =
  | { registry: string }               // "worldbank" — a REGISTRY KEY, never a URL
  | { dataset: string }                // "ds_…" — the user's own data (§4.5)

type EntitySel =
  | { ids: string[] }
  | { group: string }                  // "countries" | "g7" | "eu27" — SERVER-SIDE table
  | { all: true }

type Filter =
  | { field: string; op: "eq"|"neq"|"gt"|"gte"|"lt"|"lte"; value: string|number }
  | { field: string; op: "in"; value: (string|number)[] }
```

- **"Compare the G7 over time"** → `{entities:{group:"g7"}, range:{from:1990,to:2024}}`.
  `group` resolves **server-side from a versioned table**, never from the model's memory, so
  membership cannot vary between two runs and "is the EU a G7 participant?" is settled once,
  visibly, in data.
- **"Worst air quality"** → `{entities:{all:true}, order:{by:…,dir:"desc"}, limit:10}`. The
  shape is expressible; whether a source exists is answered by §4.7's `Refusal`.
- **"Sort my sales data, top 3"** → `{source:{dataset:"ds_x"}, order:…, limit:3}`.
- **`limit` is a query bound, not a pre-slice.** The renderer receives `limit + context` rows
  and the control stays live, so "top 3" does not destroy the interactivity that was the
  reason to draw a table instead of writing a sentence.

**Price basis is part of the query, not a caveat in prose.** `select` names the constant
series (`NY.GDP.MKTP.KD`) or the current one (`NY.GDP.MKTP.CD`); a current-US$ series sets
`comparableAcrossTime: false`, and when false **the chart carries the warning**, not only the
narration. A caveat that lives in a sentence while the misleading line lives in the persisted,
screenshot-able artifact is the wrong way round.

**`Query` is flat and tabular, and that is a real limit.** Trees, flows and networks need
nodes and edges, which this grammar cannot express. Rather than let diagram blocks bypass the
discipline every other block follows, the shape is specified now:

```ts
type GraphQuery = {
  source: SourceRef
  nodes: { select: string[]; id: string; label?: string; group?: string }
  edges: { select: string[]; from: string; to: string; weight?: string }
  filter?: Filter[]
  limit?: { nodes?: number; edges?: number }
}
```

Diagram blocks take `GraphQuery`. Nothing in Phase A uses it; it exists so that §8.3's diagram
week is building against a written shape rather than inventing one. **B2 is blocked on this
type being real**, and the schedule says so.

### 4.4 Why eight blocks and not one

The alternative worth taking seriously: a single `View {query, mark}` block, with everything
else derived from data shape. It is smaller, more general, and it removes a whole class of
model error.

Eight typed blocks earn their place for three reasons:

1. **Validation specificity.** `Choropleth.fill` can require a geographic entity selector;
   `View` cannot, so a geographic mark over non-geographic entities becomes a runtime surprise
   instead of a validation error with a repair message.
2. **Interaction is per-type, not per-mark.** Drag-rotate, column sort and legend toggle are
   not variations of one behaviour, and `tiers`/`fields`/`a11y` in `BlockDef` are per-type
   facts that a single block would have to carry as a union anyway.
3. **`Refusal` and `Note` are not views at all**, and they are two of the eight.

The cost is real and named in §8.5: the system prompt grows with every block. That is why the
core pack is 8 and not 24, why extensions are per-app rather than global, and why the encoding
*within* a block is derived rather than specified — which is where most of the single-block
idea's benefit actually lives, and it is adopted.

### 4.5 The user's own data

```
drop a file / paste  ──▶ POST /api/datasets  ──▶ parse (csv, tsv, json, xlsx)
                                              ──▶ profile; store rows server-side
                                              ──▶ return { id, profile }

type DatasetProfile = {
  id: string; name: string; rows: number
  columns: { name: string; type: "number"|"string"|"date"|"bool";
             nulls: number; sample: unknown[]; distinct?: number }[]
}
```

**The agent sees the profile, never the rows** — the same discipline `digest()` applies to
public data. A 50,000-row CSV costs roughly 200 tokens of profile. Then
`{source:{dataset:"ds_x"}}` uses the identical query grammar, so user data is not a special
case anywhere downstream. This path needs no globe, no geo join and no third-party licensing,
which is why §8.3 ships it in week one.

### 4.6 Bindings, the snapshot, and calling the agent

```ts
type Binding = { $from: { el: ElementId; field: BoundField } }
type BoundField = "selection" | "selections" | "year" | "range" | "row" | "rows" | "sort"
```

Closed objects, never parsed strings: a parsed dot-path is a mini-expression-language, and a
model-supplied value templated into a request is the injection hole §7 forbids. `selections`
(plural) exists from day one — multi-select is something users try in the first minute, and
adding cardinality later changes every consumer's shape.

**The snapshot** is what the agent reads each turn: one line per element, regenerated from
live state, never appended.

```
[space] el_01J9…A2 Choropleth  sel=[BRA] camera=USA year=2023 life=persistent
        el_01J9…B7 Metric      entity←el_01J9…A2 life=persistent
        el_01J9…C1 Table       ds=ds_sales sort=region:asc limit=3 rows=412 life=session
```

Scope: **all persistent and pinned elements, plus the 12 most recently *interacted-with*
session elements**, capped at 40 lines, with `… 12 more (use list_space)` past the cap.
Recency is by element interaction, not by turn ordinal — a space is not a transcript, and an
element you touched five turns ago is more relevant than one placed and ignored last turn. The
cap exists because this is paid on every turn and grows with the space (§8.5).

**The space calls the agent.**

```ts
type Invoke = {
  on: "press" | "submit" | "interval"
  prompt: string
  input?: { field: string }
  label: string                   // shown on the control; the user always knows
  maxDepth?: number               // author's ceiling; the SPACE's is authoritative
}

type SpaceBudget = {
  invokeCallsPerDay: number       // hard ceiling; only a user may raise it
  maxChainDepth: number           // default 2 — enforced against Element.invokeChainDepth
  intervalsEnabled: boolean       // default FALSE
}
```

Depth is **server-written, not author-declared**: `place()` issued during an invoke sets the
new element's `invokeChainDepth = placer.invokeChainDepth + 1`, and the server refuses an
invoke whose element is already at `space.budget.maxChainDepth`. An element cannot reset its
own depth, and two elements invoking each other terminate at the space ceiling rather than
each other's local one.

Four guards: **visible** (any control that will call a model says so), **depth-capped** as
above, **budgeted per space** with a ceiling only a user can raise, and **`interval` off by
default per space**. A timer that calls a model is a standing charge on a space that may
outlive anyone's interest in it; that is a human decision.

**`interval` needs a scheduler, and it is a real line item.** Firing an invoke in a space
nobody has open cannot happen in a request handler. The plan names it: a **cron trigger plus a
durable queue** (Vercel Cron or an equivalent scheduled function, with a jobs table keyed by
space and next-fire time), budgeted in §8.3 as **B3, 1.5 days**, not assumed free. It is also
the reason `intervalsEnabled` defaults to false — the feature is not free to run *or* to
build.

Failure is visible: a failed invoke leaves the element in an error state with a retry, never a
silent no-op.

### 4.7 The core pack — `packs/core/blocks.ts`

The schemas, not an index of them.

```ts
import { z } from "zod"

const Scale    = z.enum(["linear", "log", "quantile", "quantize"])
const Tone     = z.enum(["body", "note", "warning"])
const Emphasis = z.enum(["primary", "muted"])
const Align    = z.enum(["start", "end"])

/** A value that is either a literal or bound to another element's field. */
const Bound = <T extends z.ZodTypeAny>(t: T) => z.union([t, BindingSchema])

/** THE ONE DATA SHAPE. Anything that fetches takes this — there is no second ref shape. */
const DataSource = z.object({
  query:  QuerySchema,
  freeze: z.enum(["envelope", "slice"]).default("envelope"),   // §4.2
})
```

```ts
// ── 1. Prose — where §3.1 is ENFORCED ─────────────────────────────────────
const BARE_NUMERAL = /(?<![\w$#])\d[\d,.]*(?![\w%])/

export const Prose = z.object({
  text: z.string().max(4000).refine(
    s => !BARE_NUMERAL.test(s.replace(/\{\{f\d+\}\}/g, "")),
    { message: "Prose.text may not contain literal figures. Move each number into figures[] and reference it as {{f0}}." }
  ),
  figures: z.array(z.object({ ref: BindingSchema, format: z.string().optional() }))
           .max(12).default([]),
  tone: Tone.default("body"),
}).strict()

// ── 2. Metric ─────────────────────────────────────────────────────────────
export const Metric = z.object({
  group: z.array(z.object({
    label: z.string().max(60),
    value: z.union([z.number(), z.string()]).optional(),
    data:  DataSource.optional(),
    delta: z.object({ vs: z.number(), dir: z.enum(["up","down"]).optional() }).optional(),
    sparkline: z.boolean().default(false),
  }).refine(g => (g.value !== undefined) !== (g.data !== undefined),
            { message: "exactly one of value | data" })).min(1).max(6),
  emphasis: Emphasis.default("primary"),
}).strict()

// ── 3. Table ──────────────────────────────────────────────────────────────
export const Table = z.object({
  data: DataSource.optional(),
  rows: z.array(z.record(z.unknown())).max(200).optional(),
  columns: z.array(z.object({
    field: z.string(),
    label: z.string().optional(),
    align: Align.optional(),                    // §4.9's admitted exception
    format: z.enum(["number","currency","percent","date","text"]).optional(),
  })).max(24).optional(),
  sort:    z.object({ by: z.string(), dir: z.enum(["asc","desc"]) }).optional(),
  groupBy: z.string().optional(),
  caption: z.string().max(200).optional(),
}).refine(t => (t.data !== undefined) !== (t.rows !== undefined),
          { message: "exactly one of data | rows" })

// ── 4. Chart ──────────────────────────────────────────────────────────────
export const Chart = z.object({
  data: DataSource,
  mark: z.enum(["line","bar","area","point"]).optional(),   // HINT; encoding is derived
  x: z.string().optional(),
  y: z.string().optional(),
  series: z.string().optional(),
  scale: Scale.optional(),
  stack: z.boolean().default(false),
  legend: z.boolean().default(true),
}).strict()

// ── 5. Choropleth — THE RECONCILIATION ────────────────────────────────────
// `fill` is DataSource + channel config. It is NOT a second kind of ref.
export const Choropleth = z.object({
  fill: DataSource.extend({
    scale:   Scale.default("log"),        // population spans nine orders of magnitude
    legend:  z.boolean().default(true),
    palette: z.enum(["sequential","diverging"]).default("sequential"),

  projection: z.enum(["orthographic","natural","mercator"]).default("orthographic"),

  year: Bound(z.number().int()).optional(),

// `highlight` is the STROKE/halo channel; `fill` is the polygon CAP. Orthogonal — no
// precedence rule is needed, and "show me America" can light the US *and* show its value.

// ── 6. Stack ──────────────────────────────────────────────────────────────

  gap: z.enum(["s","m","l"]).default("m"),

// children are ids, so patching, freezing and the snapshot never need to recurse.
```

### 4.8 Tool definitions

One discriminated `place` tool over the block union, not eight tools — eight would multiply
the schema in every system prompt and make adding a block a prompt change.

```ts
place  ({ name: string, block: string, props: object, lifetime?: Lifetime, layout?: Layout })
update ({ el: ElementId, props?: object, lifetime?: Lifetime })
remove ({ el: ElementId })
query  ({ ...Query })                       // returns a digest, never rows
list_space ({ filter?: "all"|"persistent" })
```

`place.props` validates against `block`'s schema after the discriminator is read. This is the
shape A1's strict-mode spike must test, because `strict: true` and a discriminated union over
eight schemas is exactly where provider grammar support tends to break.

### 4.9 Prop rules

1. **Data-shaped, not pixel-shaped.** No `width`, `margin`, `className`. Colour only through
   semantic enums. *Admitted exception:* `align` on table columns — the model knows a column
   is numeric before the theme does.
2. **Flat, except per-column and per-series descriptors.** Tables are irreducibly configured;
   that is why TanStack Table is headless.
3. **Enums over free strings.** *Admitted exception:* `iso3`, validated against the geo table.
4. **≤8 props, ≤3 required.** `Table` and `Chart` are exempt and documented.
5. **Everything optional renders.** A half-streamed spec must draw something.
6. **`settled`, defined:** a block is settled when the tool call that produced it closes, **or**
   after 400 ms with no new patch — whichever comes first, because a stream can simply pause.
   A settling element **reserves its declared `minH` from mount**, so resolving it never
   shoves what is below it down the page.
7. **Mobile behaviour is declared per block** in `BlockDef.mobile`, at 8 blocks, not later
   at 24.

## 5. Assets

### 5.1 What ships, and how a licence is established

**[measured 2026-09-19, npm registry]**

| Pack | Version | Licence | Verdict |
|---|---|---|---|
| `lucide` | 1.47.0 | **ISC** | **Ship.** Permissive, no attribution burden, one visual system. |
| `material-symbols` | 0.47.4 | **Apache-2.0** | **Ship** as the fallback set. |
| `@fontsource/inter` | 5.3.0 | **OFL-1.1** | Ship. Self-hosting is distribution → `licenses/` build step. |
| `openmoji` | 17.0.0 | **CC-BY-SA-4.0** | **Not in core.** |

**OpenMoji is the share-alike trap in a new place.** Copyleft propagates: shipping CC-BY-SA
art inside a themed pack puts an obligation on the pack, and every downstream commercial user
inherits it. Optional pack flagged `shareAlike: true`, or it does not ship. The same test cut
Open-Meteo (§6.4). It is a standing rule applied before adoption, not a discovery made once
per round.

**Sprites and pixel art — the method, because the claim could not be verified remotely.**
**[measured 2026-09-19]** game-icons.net states **CC BY 3.0** on its own about page.
**Kenney could not be machine-verified**: `kenney.nl/assets` returns HTTP 200 but the licence
text is JS-rendered, `kenney.nl/license` 404s, Kenney's own GitHub repos carry **MIT**
(the starter kits), and a third-party mirror carries **CC0-1.0**. Widely-repeated CC0 is not
evidence.

The conclusion is a method rather than a guess: **the authoritative licence for an art pack is
the licence file shipped inside the pack you actually downloaded**, pinned by checksum. The
audit reads that file, records `{spdx, attribution, commercialUse, sha256}` per pack, and CI
fails any asset with no recorded licence — the same gate §6.4 applies to data sources. Until
that audit runs, **sprite sourcing is the least-verified claim in this document**, and it is
flagged here rather than at the bottom of a phase table.

### 5.2 Addressing

```ts
type AssetRef = { pack: string; name: string; v?: string }
```

Never a URL, never a path — the same closed-reference rule as `source` and for the same
injection reason. An unknown asset resolves to a labelled placeholder, never a broken image.

### 5.3 "On theme" is a recolour pipeline, not a generator

**Do not plan to generate sprites.** On-theme pixel art at consistent quality is not a week of
work and does not belong on the critical path of a project whose thesis is elsewhere.

What is cheap and captures most of the value: **a build-time recolour pass.** Art is sourced
or authored in a flat indexed palette; `tokens.json` maps palette slots to theme ramps; the
emitter produces a variant per theme. Flip the token file and the sprites change with the CSS
— which is what makes §8.6's theme demo more than a palette swap.

**Authoring, since the brief names painting software:** **Aseprite** for pixel art (indexed
palettes and palette swapping are native to it, which is exactly what the recolour pipeline
consumes) and **Inkscape** for SVG chrome. Both export the indexed formats the pipeline wants;
neither introduces a licence obligation on output. This is a tooling recommendation, not a
dependency — the pipeline's input is an indexed PNG or an SVG, whatever drew it.

**3D and meshes are deferred, explicitly.** The brief mentions mesh/model software. A 3D tier
means a format decision (glTF), a renderer that is not the SVG/DOM one, a licence surface, and
an accessibility story with no good answer. It is a second product. Deferred with reasons —
and §1.2's persistence argument is *stronger* for a 3D scene than for a chart, so this is a
real future direction rather than a polite no.

### 5.4 Tokens

Source of truth is `tokens.json` (DTCG-shaped), **not a CSS file** — CSS custom properties
never reach a canvas `fillStyle`. Emitters produce `theme.css`, `tokens.ts`, a GPT-Vis/G2
theme object, and the sprite palette maps. Ramps authored in OKLCH so light and dark derive
from one definition; separate categorical data palette, contrast-validated in **both** themes.

**Bounded honestly:** one token source generating CSS variables, a G2 theme object, a
validated palette and the sprite recolours is about a week. **"A canvas chart and a DOM card
look pixel-identical" is not deliverable** and is not claimed: canvas has no CSS cascade, and
G2 re-derives ramps through d3-color in sRGB, voiding OKLCH evenness exactly at the choropleth
legend. What breaks first and most visibly is the **dark-mode toggle** — CSS flips instantly
while canvas lags, through a different API. Budget a runtime theme-push on `matchMedia`.
Staying on SVG/DOM for slice 1 makes this mostly moot.

## 6. The spatial block, and the data layer

### 6.1 `d3.geoOrthographic`, not WebGL

A drag handler updating `.rotate([λ, φ])` gives a spinnable globe from the *same* `d3-geo` and
the *same* topojson already loaded.

**Measured sizes** (esbuild + gzip -9; bundlephobia reports a broken 709 B for `d3-geo`):
`d3-geo` alone **14.7 KB gz**; the realistic day-1 set (`d3-geo` + `topojson-client` +
`d3-scale` + `d3-scale-chromatic`) **17.8 KB gz**; plus `world-atlas` 110m at **38.4 KB gz**.
**~56 KB against ~600 KB.**

Deleted from the critical path: a ~559 KB gz / 2.0 MB parsed bundle; `h3-js` (213 KB, for a
hexbin layer never used); a static `three/webgpu` import (2.28 MB) whose tree-shaking is a coin
flip; three copies of three.js (globe.gl pins it, three-globe peers it, json-render ships an
R3F renderer) failing as silent `instanceof` errors; and **`globe.gl` reading `window.THREE` at
module scope, which throws in Node** and would have forced `dynamic(ssr:false)`, keeping the
globe out of the server-streamed paint.

**Scoped honestly.** "~30 lines" is the *rotate handler*. Canvas hit-testing, the fill scale,
the legend, the halo channel, `settled` and the mobile scroll rules are not in it. The block is
**~3 days**, of which rotation is an hour. **"60fps on a phone at 177 polygons" is
[asserted]** — the one performance number in a document that measures everything else — and it
gets measured in A4 on a real mid-range device.

### 6.2 The country-code join

`world-atlas` features carry only `{name}` in `properties`, but **their `id` is the ISO-3166-1
numeric code** as a zero-padded string (`"840"`, `"250"`). Missing that is what made earlier
estimates read in days.

**[measured]** `numericToAlpha3` resolves **174 / 177**. Joined to the live World Bank list
(`region.id !== 'NA'` → 217 countries): **169 / 174**. **Total hand-adjudication: one override
(Kosovo → `XKX`).** Generated at build time and vendored: **175 entries, 902 bytes gzipped.**

**The exclusion list, as one list:** N. Cyprus, Somaliland, Kosovo *(no `id` in world-atlas)*;
W. Sahara, Falklands, Fr. S. Antarctic, Taiwan, Antarctica *(valid ISO code, no World Bank
row)*. Eight of 177. The CI test — "every polygon either joins or is on this list" — is ~15
lines.

**Stay on 110m.** 50m is 230 KB gz *and makes the join worse*: five no-id features plus a
duplicate id `036` shared by Australia and Ashmore & Cartier, so `new Map(...)` silently drops
Australia.

**`focus` needs a vendored camera table — a separate ~half-day**, not folded into the join.
Computed centroids fail: `geoCentroid(France)` is open ocean off Portugal (French Guiana drags
it); `geoBounds` on Russia and Fiji returns `maxLon < minLon` across the antimeridian; the
USA's bounds span 105° because of the Aleutians. ~40 entries, generated once, hand-corrected.

**Disputed boundaries are data, not contract.** Natural Earth encodes editorial choices on
Kashmir, Crimea, Taiwan and Western Sahara. `entities:"countries"` stays defined by World
Bank's own `region.id !== 'NA'`, and territory policy lives in **versioned geo data with an
override map** — never a `"sovereign"` enum in a block schema, which would force every
conforming renderer to agree on a list of sovereigns in order to be conformant.

**Mobile rules, in `BlockDef.mobile`:** wheel never zooms; globe ≤55vh so there is always a
scroll gutter; below 600px a one-finger drag must not steal page scroll. Pinch zooms.

### 6.3 `digest()` — why the naive version launders errors

The model never sees rows. It calls `digest()` and narrates from that. The naive nine-field
version `{min,max,first,last,delta,cagr,units,n,outliers}` is dangerous — **[measured against
the live API, re-verified by a second reviewer 2026-09-19]**:

- **It truncates silently.** World Bank's default `per_page` is **50**. A BRA+USA 1990–2024
  call has `total=70`, returns 50, and the USA's present years become **exactly 2010–2024** —
  so `first` is 2010, not 1990, and `delta` spans 14 years instead of 34. Well-formed object,
  wrong numbers, HTTP 200 throughout.
- **`units` cannot be populated.** The `unit` field is an **empty string** on both the
  observation and the indicator metadata; it must be scraped from the indicator name.
- **Nominal vs real is unrepresentable.** Brazil's GDP CAGR is **5.24%** current US$ and
  **2.36%** constant 2015 US$. The series shows a 44% "collapse" 2011→2020 that is almost
  entirely currency depreciation. `outliers` makes it worse: those years are FX artifacts, and
  flagging them invites the model to narrate them as economic events.
- **`n` hides gaps.** Syria 1990–2024 has 2 nulls. Two series with `n:33` can be consecutive or
  war-shaped, and the model draws a trend line through the hole.

A digest that cannot say "this number is not comparable across time" is not a safety
mechanism. It is a laundering mechanism: it converts the model's uncertainty into a structured,
authoritative-looking object.

```ts
{ first: {year, value}, last: {year, value}, min, max,
  n, nMissing, gaps: [[y, y]],
  cagr, priceBasis: "current" | "constant-2015" | "ppp", currency,
  comparableAcrossTime: boolean,
  units, unitsSource,
  series12: [...],        // ≤12-point resample — closes the whole
                          // "when did X happen / who overtook whom" class
  caveats: string[] }     // current-US$ emits a MANDATORY caveat that §4.3
                          // routes onto the CHART, not just the prose
```

`NY.GDP.MKTP.KD` (constant) and `NY.GDP.PCAP.CD` (per capita) ship first-class — per capita is
usually the honest answer to "why is it behind" ($10.3k vs $86k), and the naive digest pushes
the model toward the wrong comparison.

### 6.4 The resolver

**Server-side.** Not for CORS — World Bank sends `access-control-allow-origin: *` — but
because rate limits would be charged against each end user's IP, browsers cannot set the
`User-Agent` Wikimedia's policy requires, and there is no cross-user cache. Its work:
pagination, aggregate filtering, cache keying with the resolver version in the key,
single-flight dedup, and **a monotonic request token per element** so tapping Brazil-then-China
quickly cannot leave Brazil's data under China's label.

**Abort tokens ship in Phase A.** A counter and a comparison, not five weeks of work, and
deferring them guarantees the mislabelled-data bug is live during the exact period anyone is
watching.

Error taxonomy from measured behaviour: a bad indicator returns **HTTP 200 with an error
envelope** **[measured, re-verified]**; the genuinely silent case is a *valid* code with no
data → `value: null`.

**Licensing, all verified.** World Bank CC-BY, attribution propagates to every rendered chart
and into `FrozenData.receipts`. **Open-Meteo's free tier is non-commercial only — cut from
defaults**, or every downstream commercial user inherits a ToS breach. **Wikipedia is
client-impossible** (the `User-Agent` its policy requires cannot be set in a browser) and
CC BY-SA share-alike. REST Countries is an unmaintained single point of failure — vendor a
snapshot. Every `ResolverDef` carries `licence`; CI fails one without an attribution string and
generates `THIRD_PARTY_DATA.md`.

## 7. Safety

**7.1 Rendering.** `Prose` renders markdown through a named sanitizer, no raw HTML. Images
resolve through the asset registry or an allowlist proxy. No prop accepts an arbitrary URL
scheme.

**7.2 References are closed.** `source` is a registry key, `AssetRef` is a pack/name pair, and
bindings are closed objects. Nothing model-supplied is templated into a URL, which is one rule
covering three surfaces.

**7.3 Third-party packs.** A resolver is a declarative descriptor, not code (§2.3): fixed
host from `base`, named slots only, egress allowlist checked at install *and* resolve time
against the resolved address, JSONPath extraction with no `eval`. A block's `render` **is**
code, so third-party *block* packs are trusted code and install is an explicit, warned action —
the same trust level as a dependency, stated rather than implied. Untrusted third-party blocks
would need the sandbox §2.3 defers.

**7.4 Uploads and invoke.** Datasets: size caps, parser timeout, type sniffing rather than
trusting the extension, per-space quota shared with `FrozenData` (§4.2), formula stripping on
xlsx ingest, never cross-readable between spaces. Invoke: server-side depth counting, a budget
only a user can raise, and no user free-text reaching a prompt without the same validation a
turn gets.

**7.5 Accessibility is a requirement, not polish.** It is the most expensive retrofit and the
one that blocks shipping commercially, so `a11y` is a **required field in `BlockDef`** (§2.2) —
a block without a role and a keyboard path does not register.

- **SVG/DOM is the default substrate**; canvas is an optimisation adopted only where measured,
  always with a DOM shadow tree carrying the same data.
- The globe: arrow keys rotate, `Tab` cycles countries in fill order, `Enter` selects.
- Every data block exposes a **table view of its own data**, which doubles as the copy/export
  affordance.
- The conformance suite runs axe; the static-SVG renderer makes "what does this element *say*"
  mechanically answerable.

### 8.5 What it costs

**Tokens** **[asserted — arithmetic over stated budgets, measured in A6]:**

| Item | Tokens |
|---|---|
| System prompt (8 blocks + query grammar + capabilities) | ~2,000–3,000 |
| Space snapshot at the 40-line cap | ~600 |
| One `place()` spec | ~250 |
| One digest with `series12` | ~400 |

The system prompt grows with every block added — the real scaling cost of the approach, and

**Storage** **[asserted]:** a frozen `Choropleth` envelope over 217 entities × 35 years of one

compacts to 10 versions and why the quota is shared with datasets and shown in the UI. Object
storage at that size is cents per space per year; the cost that actually bites is unbounded
version growth, which is why it is bounded.

### 8.6 Done looks like

The recording proves **the space**, and is scoped to that claim:

A stranger opens a space, drops in a CSV, gets a sortable table. They ask about America, get
prose immediately and a globe they can drag, tap Brazil, scrub the year — no model calls. They
close the tab. **They come back the next day and it is all there**, rendering from frozen data,
showing the same numbers. They pin one element, let another expire and watch it leave a stub
rather than vanish. Then they flip one token file and the identical space re-renders as a
visibly different product, sprites and all.

**Then the part that is not rehearsed:** the skeptic types three prompts of their own, one
deliberately out of vocabulary, and the system says precisely what it cannot do instead of
bluffing. A recording cannot distinguish a generated spec from a fixture — especially in a
codebase that contains fixture replay — so unrehearsed input from the person being convinced is
the only thing that can. Refusal is this plan's strongest and least-shown idea.

**The falsifiable claim is A6's**, not the film: 20 prompts × 3 samples, ≥80% block-type match,
zero invalid codes, zero unrefused out-of-vocabulary prompts, threshold written first. If the
